# Comic OCR Studio 4.32

برنامهٔ مستقل Python برای کار روی کمیک، مانگا، کتاب، مقاله و جزوه: **PDF یا تصویر ورودی → OCR هوشمند (کمیک و کتاب) → ترجمه (رایگان آنلاین، مترجم آفلاین داخلی NLLB-200 بدون اینترنت یا AI) → ویرایش → PDF، ZIP تصویر، TXT، Word (DOCX تصویری و کتابی پیوسته) یا PowerPoint (PPTX تصویری و اسلاید ارائه ۱۶:۹)**.

این برنامه به افزونه وصل نمی‌شود و هیچ تصویری از وب‌سایت جمع‌آوری نمی‌کند. افزونه فقط جمع‌آورندهٔ تصاویر سایت باقی می‌ماند.

**محدودیت فعلی ذخیره:** یک پروژه را هم‌زمان در چند تب یا دستگاه ویرایش نکنید؛ ذخیرهٔ یک نمای قدیمی می‌تواند تغییرات جدید را بازنویسی کند. تا رفع کنترل نسخهٔ سراسری، پیش از کار بک‌آپ بگیرید و فقط از یک تب استفاده کنید.


### نتیجه‌های منتظر و تعارض

ورود تصویر/PDF پس از پردازش به آخرین وضعیت پروژه اضافه می‌شود. OCR و ترجمهٔ پروژه تغییرات نامرتبط را حفظ می‌کنند؛ اگر صفحه یا کادرِ هدف در حین کار تغییر کند، پنجرهٔ مقایسه نشان داده می‌شود. برای هر مورد «حفظ ویرایش فعلی» یا «استفاده از نتیجهٔ آماده» را انتخاب کنید؛ موارد بدون تعارض اعمال می‌شوند. تصویر/کادر حذف‌شده دوباره ساخته نمی‌شود. با حفظ یک کادر ترجمه، خلاصهٔ تازه هم جایگزین خلاصهٔ قبلی نمی‌شود. پس از ثبت تعارض، برای درخواست‌های باقی‌مانده پیش‌نمایش را دوباره بررسی کنید؛ ادامهٔ خودکار ارسال نمی‌شود. اگر نوبت یا checkpoint عوض شده باشد نتیجه فقط قابل کپی است. برای دیدن نتیجه پس از بازکردن دوبارهٔ پروژه از دکمهٔ **نتایج منتظر بررسی** کنار گزارش استفاده کنید؛ حذف نتیجه تأیید می‌خواهد و ارسال مجدد همان مرحله تا بررسی/حذف نتیجه مسدود است.

نتیجهٔ OCR و پاسخ معتبر AI/free در فایل محلی جداگانهٔ پروژه در `.pending-results` نگهداری می‌شود و تا ثبت یا حذف می‌ماند؛ کلید API را عمداً در آن نمی‌نویسیم، اما حاوی متن‌ها و خلاصهٔ خصوصی است. در POSIX پوشه `0700` و فایل‌ها `0600` ساخته می‌شوند؛ در Windows امنیت به ACL پوشهٔ کاربر وابسته است، و رمزگذاری وجود ندارد. **این فایل‌ها داخل ZIP بک‌آپ نیستند**؛ پیش از انتقال، نتیجه را بررسی و ثبت یا جداگانه کپی کنید. حذف پروژه نتیجه‌های منتظر آن را هم حذف می‌کند. از حافظه و فایل‌ها به‌تناسب محرمانگی محتوا محافظت کنید.

در صورت پرشدن دیسک یا حذف پروژه پس از پاسخ، اگر ذخیرهٔ موقت ناموفق شود، برنامه در صورت برقرار بودن ارتباط، متن معتبر دریافتی را برای کپی در پنجره نشان می‌دهد؛ آن را پیش از بستن پنجره کپی کنید. قطع برنامه/برق پیش از ذخیرهٔ موقت یا قطع شبکه هنگام دریافت پاسخ همچنان می‌تواند نتیجه را از بین ببرد؛ سرویس ممکن است درخواست را پردازش کرده باشد و تکرار آن هزینه داشته باشد. پاسخ نامعتبر از روش اصلاح موقت نسخهٔ قبلی استفاده می‌کند و با راه‌اندازی مجدد بازیابی نمی‌شود. قفل‌ها فقط یک فرایند برنامه را پوشش می‌دهند. محدودیت ذخیرهٔ چندتب/چندفرایند گفته‌شده در بالا همچنان برقرار است؛ ویرایش هم‌زمان را تضمین نمی‌کند.

### API ویرایشگر مستقل

در صفحه‌ای بدون build ابتدا `rich-editor.css`، سپس `rich-sanitize.js` و `rich-editor.js` را از `comic_studio/static` بارگذاری کنید و یک عنصر میزبان بسازید:

```html
<div id="editor"></div>
<script src="rich-sanitize.js"></script>
<script src="rich-editor.js"></script>
<script>
  const editor = createEditor('#editor', { autosaveKey: 'my-document', initialHTML: '<p>Hello</p>', onChange: html => console.log(html) });
  // editor.setHTML('<p>Replacement</p>');
  console.log(editor.getHTML(), editor.getText());
  editor.focus();
  const unsubscribe = editor.onChange(html => console.log('changed', html));
  // unsubscribe(); editor.destroy();
</script>
```

`setHTML` و جابه‌جایی بین تب‌ها خروجی را sanitize می‌کنند؛ پیش‌نویس محلی با `autosaveKey` اختیاری است. سازگاری ویرایش بصری به `contenteditable` و `execCommand` مرورگر وابسته است؛ هیچ کتابخانه یا مرحلهٔ build اضافه نشده است.

## نصب برنامه از GitHub

برای نصب **خود برنامه** از مخزن اصلی، در ویندوز این کارها را انجام دهید:

1. Python ۶۴ بیتی سازگار (۳.۱۱ تا ۳.۱۳) و Git را نصب کنید. در نصب Python گزینهٔ **Add Python to PATH** را فعال کنید.
2. PowerShell را در پوشه‌ای که می‌خواهید برنامه در آن باشد (در هر درایو دلخواه مثل `C:` یا `D:`) باز کنید و اجرا کنید:

```powershell
git clone https://github.com/sargoliwork101-ui/COMICCCC.git
cd COMICCCC\python_app
.\start_windows.bat
```

اگر Git ندارید، صفحهٔ [مخزن اصلی](https://github.com/sargoliwork101-ui/COMICCCC) را باز کنید، از **Code → Download ZIP** فایل را بگیرید، آن را Extract کنید و سپس داخل پوشهٔ `python_app` فایل `start_windows.bat` را اجرا کنید. لازم نیست مخزن‌های مدل‌های دیگر را برای نصب برنامه دانلود کنید.

همهٔ ۱۴ مدل OCR فهرست‌شده در پنجرهٔ «مدیریت مدل‌های OCR» با یک کلیک روی دکمهٔ «آماده‌سازی / دانلود خودکار» به‌صورت خودکار نصب و دانلود می‌شوند؛ مدل‌های سنگین نیز در محیط‌های مجازی ایزولهٔ مخصوص خودشان (`models/envs/<engine>`) آماده می‌شوند تا با محیط اصلی برنامه تداخلی نداشته باشند.

### تغییر اختیاری مسیر دانلودها و انتقال برنامه به درایو دیگر (خارج از درایو C)

- **تغییر اختیاری پوشهٔ دانلودها و اطلاعات برنامه از داخل تنظیمات:** به‌طور پیش‌فرض اطلاعات و مدل‌های دانلودشده در پوشهٔ کاربر (`~/.comic-ocr-studio`) ذخیره می‌شوند. اگر فضای درایو `C` شما کم است، می‌توانید از منوی **«پروژه و تنظیمات ← مسیر ذخیره‌سازی و دانلودها (اختیاری)»** (یا دکمهٔ **«مسیر دانلودها…»** در پنجرهٔ مدل‌ها) هر پوشه‌ای در درایو دیگر (مثلاً `D:\ComicOCRStudio`) انتخاب کنید تا تمام دانلودهای موتورهای OCR، کش‌های نصب موقت، پروژه‌ها و تنظیمات مستقیماً در همان پوشه قرار بگیرند. در صورت فعال‌بودن گزینهٔ انتقال خودکار، فایل‌های فعلی ابتدا به‌طور کامل کپی و تأیید سلامت می‌شوند و سپس فضای مسیر قبلی آزاد می‌گردد. اگر روزی درایو اکسترنال انتخابی موقتاً جدا باشد، برنامه بدون خطا موقتاً با مسیر پیش‌فرض بالا می‌آید و تنظیم شما را حفظ می‌کند.
- **جابه‌جایی کل پوشهٔ خود برنامه (`python_app`) به درایو یا مسیر جدید:** هر زمان بخواهید کل پوشهٔ برنامه را به درایو دیگری منتقل کنید، کافی است برنامه را ببندید، پوشهٔ `python_app` را به مسیر جدید ببرید و از همان‌جا `start_windows.bat` (یا `run.py`) را اجرا کنید؛ راه‌انداز به‌صورت خودکار تغییر مسیر پوشه را تشخیص می‌دهد و مسیر داخلی `.venv` را بدون پاک‌کردن بسته‌ها اصلاح می‌کند.

### تنظیم منابع سیستم (رم و پردازنده) — نسخهٔ ۴.۲۹

- اگر هنگام خواندن متن یا ترجمه، سیستم شما کند یا هنگ می‌کند، از منوی **«☰ پروژه و تنظیمات ← تنظیم منابع سیستم (رم و پردازنده)»** باز کنید. در این پنجره مشخص است سیستم شما چند هسته پردازنده و چند گیگابایت رم دارد و می‌توانید درصد دلخواه **پردازنده** و **حافظه** را برای برنامه تعیین کنید.
- **اثر آن روی برنامه:** درصد پردازنده تعداد هسته‌های مجاز را در همهٔ موتورهای OCR، ترجمهٔ آفلاین و موتورهای ایزوله اعمال می‌کند و درصد حافظه تعداد صفحه‌هایی را که هم‌زمان پردازش می‌شوند کم می‌کند. برای سیستم‌های ضعیف، «پردازنده ۲۵٪ تا ۴۰٪» و «حافظه ۴۰٪ تا ۶۰٪» پیشنهاد می‌شود.
- حالت **«خودکار»** (پیش‌فرض) رفتار همیشگی برنامه را نگه می‌دارد. انتخاب شما در کنار بقیهٔ تنظیمات ذخیره می‌شود و از همان لحظه اعمال می‌گردد.

### ماندگاری کلید و لایسنس — نسخهٔ ۴.۳۲

در نسخهٔ ۴.۳۲ ریشهٔ نگرانی «کلید نباید هر بار پاک بشه» از بین برداشته شد:

- **کلید عمومی عمداً داخل خود برنامه می‌ماند** (در `comic_studio/_public_key.py` و کامپایل‌شده داخل `EXE`) و به پوشه‌های قابل‌ویرایشِ کاربر منتقل نمی‌شود؛ چون اگر برنامه کلید را از جایی بخواند که کاربر می‌تواند تغییرش دهد، هر کسی می‌تواند با یک ویرایش ساده لایسنس جعلی بسازد و کل سیستم لایسنس بی‌ارزش شود.
- **لایسنس خودِ شما هیچ‌وقت با آپدیت پاک نمی‌شود:** وضعیت لایسنس (کلیدهای فعال‌شده، زمان مصرف‌شدهٔ مهلت آزمایشی و سوابق ضد دستکاری ساعت) در سه جای جداگانه **خارج از پوشهٔ برنامه** ذخیره می‌شود: پوشهٔ داده‌های کاربر، پوشهٔ تنظیمات کاربر و رجیستری ویندوز؛ پس به‌روزرسانی، نصب دوباره یا پاک کردن پوشهٔ برنامه هیچ اثری روی لایسنس شما ندارد.
- **فایل کلید داخل برنامه اکنون خودترمیم است:** هر بار که پنل فروشنده (`start_license_manager.bat`) اجرا می‌شود یا بستهٔ آفلاین ساخته می‌شود، کلید اعتبارسنجی (دقیقاً ۳۲ بایت و یک نقطهٔ معتبر `Ed25519`) و در صورت خرابی (کلید روی دو خط، مقدار کهنه یا فایل گم‌شده) به‌شکل استاندارد و یک‌خطی بازنویسی می‌شود؛ نوشتن هم اتمیک است، پس قطع برق یا بسته شدن ناگهانی برنامه نمی‌تواند فایل را نیمه‌کاره رها کند.
- **کلید مادر فروشنده نسخهٔ پشتیبان خودکار دارد:** یک کپی دوم در `~/.comic-ocr-studio-seller/backup/` نگهداری می‌شود و اگر فایل اصلی پاک یا جابه‌جا شود، کلید **خودبه‌خود برگردانده** می‌شود. دیگر هیچ‌وقت بی‌صدا کلید تازه ساخته نمی‌شود (چون کلید تازه همهٔ لایسنس‌های صادرشده را از کار می‌اندازد)؛ در این حالت پنل فروشنده هشدار روشن نشان می‌دهد و ساخت کلید تازه فقط با تأیید صریح فروشنده انجام می‌شود.
- **اگر فایل کلید برنامه آسیب دیده باشد، برنامه دیگر بی‌صدا نمی‌میرد:** یک پیام فارسی روشن می‌بینید («کلید عمومی برنامه در دسترس نیست…») و کافی است برنامه را یک‌بار دوباره نصب کنید؛ لایسنس شما در جای خودش سالم مانده است.

### خواندن سریع‌تر صفحه‌ها — نسخهٔ ۴.۳۱

در نسخهٔ ۴.۳۱ علت اصلی کند شدن خواندن متن پیدا و از ریشه برطرف شده است:

- **یک صفحهٔ پُر از حباب، چند برابر سریع‌تر:** موتور «پیدا کردن متن» برای هر حباب گفتگو، تصویر را آن‌قدر بزرگ می‌کرد که پیدا کردن متن در یک حباب، از خواندن کلِ صفحه هم گران‌تر می‌شد. حالا اندازهٔ تصویرِ دیده‌شده توسط موتور برای هر حباب محدود می‌شود، ولی خودِ متن همچنان از تصویر اصلی و با کیفیت کامل خوانده می‌شود؛ بنابراین **نتیجهٔ خوانده‌شده حتی یک حرف تغییر نمی‌کند**.
- **جدول‌های فارسی، ده‌ها برابر سریع‌تر:** برای هر خانهٔ جدول، برنامه دیگر کلِ مسیر «پیدا کردن متن + خواندن متن» را از صفر تکرار نمی‌کند؛ یک خانهٔ تک‌خطی مستقیم و فقط از روی همان بخشی که متن دارد خوانده می‌شود و خانه‌های چندخطی هم با «پیدا کردن متن» محدودشده خوانده می‌شوند (که حتی متنِ خانهٔ چندخطی را درست‌تر از قبل می‌خواند).
- **نتیجهٔ اندازه‌گیری روی یک رایانهٔ دو هسته‌ای** (پیش و پس از تغییر، با همان تصویرها): خواندن ۶ حبابِ یک صفحهٔ کمیک از **۱۸ ثانیه به ۱٫۵ ثانیه**، خواندن خانه‌های جدول از **۵٫۹ ثانیه به ۰٫۱۳ ثانیه**، و کلِ زنجیرهٔ خواندنِ یک صفحهٔ ضعیف از **۲۲ ثانیه به ۱۰ ثانیه** رسید. خواندن یک صفحهٔ معمولی و سالم **هیچ تغییری نکرد** (۲٫۰۵ ← ۱٫۹۶ ثانیه). روی رایانهٔ قوی‌تر این اعداد کوچک‌تر می‌شوند.

### خودترمیمی شدن برنامه و «تلاش دوباره» — نسخهٔ ۴.۳۰

در نسخهٔ ۴.۳۰ چند ایراد هم‌خانوادهٔ «برنامه بالا نمی‌آید / کاری انجام نمی‌دهد» از ریشه برطرف شده‌اند:

- **تبِ در پس‌زمینه دیگر سرور را نمی‌بندد:** مرورگرها تب‌های پس‌زمینه را بعد از چند دقیقه «منجمد» می‌کنند و تایمرهای آن‌ها متوقف می‌شود. پیش‌تر سرور محلی این سکوت را «بستن تب» می‌فهمید و خاموش می‌شد؛ حالا برنامه چنین تبی را «ساکت» می‌داند، سرور را نگه می‌دارد و وقتی کاربر برمی‌گردد، محیط کار مثل قبل آماده است. فقط بستن واقعی تب (یا گذشت زمان طولانی بی‌پاسخی) سرور را می‌بندد.
- **بالا آمدن دوباره با تلاش مجدد:** اگر اولین درخواستِ هنگام باز شدن برنامه قطع شود، برنامه خودش چند بار دیگر تلاش می‌کند و محیط کار را بالا می‌آورد؛ دیگر لازم نیست برنامه را ببندید و دوباره باز کنید.
- **نوار «ارتباط با برنامهٔ محلی قطع شد»:** اگر سرور محلی از کار بیفتد، به‌جای صفحهٔ مرده یک نوار فارسی با دکمهٔ «تلاش دوباره» می‌بینید که با یک کلیک برنامه را دوباره وصل می‌کند.
- **مرورگر فقط وقتی باز می‌شود که برنامه واقعاً پاسخ بدهد:** راه‌انداز پیش از باز کردن مرورگر، پاسخ واقعی `/api/health` را می‌گیرد؛ بنابراین دیگر صفحهٔ خالی «در حال بارگذاری» دیده نمی‌شود و اگر برنامه نتواند بالا بیاید، یک کادر پیام فارسی روی صفحه نمایش داده می‌شود.
- **قفل نصب مدل دیگر بی‌صدا معطل نمی‌کند:** اگر هم‌زمان درخواست دیگری برای دانلود/حذف مدل در جریان باشد، درخواست شما به‌جای انتظار طولانی، پیام فارسی روشن می‌گیرد.
- **پردازشگرِ OCR پس از بسته شدن برنامه باقی نمی‌ماند:** پردازشگر ایزولهٔ OCR حالا پیوسته زنده بودن برنامه را بررسی می‌کند و اگر برنامه بسته یا کشته شود، خودش را می‌بندد و رم چندگیگابایتی را آزاد می‌کند.
- **آزادسازی خودکار حافظهٔ مدل‌های داخلی:** مدل‌های داخلی `RapidOCR` و `EasyOCR` هم مثل مدل‌های جداگانه، پس از چند دقیقه بی‌کاری رم را پس می‌دهند.

### ساخت فایل اجرایی مستقل یک‌کلیکی (`.exe`) و نصاب آفلاین ویندوز

اگر می‌خواهید برنامه را بدون نیاز به نصب پایتون و بدون نیاز به اینترنت (مثلاً روی سیستم دیگر یا از روی فلش) با یک کلیک اجرا یا نصب کنید، داخل پوشهٔ `python_app` فایل **`build_windows_offline.bat`** را اجرا کنید:
- **حالت ۱ (`Standard Offline Setup`):** ساخت `dist\ComicOCRStudio\ComicOCRStudio.exe` و نصاب یک‌کلیکی `dist\ComicOCRStudio-Offline-Setup-4.32.exe` همراه با مدل‌های پایهٔ OCR آفلاین و مهلت آزمایشی خودکار ۲۴ ساعته (با اعلان شماره تماس `09361111111` و نمایش زندهٔ مدت اعتبار باقی‌ماندهٔ لایسنس در بالای برنامه).
- **پنل صدور لایسنس ماژولار مخصوص فروشنده (`start_license_manager.bat`):** ابزار جداگانهٔ فروشنده با ظاهر، فونت آفلاین «وزیرمتن» (`Vazirmatn.woff2`) و تم روشن/تیرهٔ یکسان با برنامهٔ اصلی برای تعریف کلید مادر ۲۵۶ بایتی اختصاصی، تنظیم اطلاعات تماس داخل `EXE`، بانک مشتریان (CRM) و صدور کلیدهای لایسنس آفلاین متصل به سخت‌افزار (`Ed25519`) با امکان تعیین مستقل وضعیت و مدت اعتبار برای هر یک از سه ماژول **«OCR»، «ترجمه» و «ویرایش»** بدون قرار گرفتن کلید خصوصی در بستهٔ نصبی مشتری.
- **حالت ۲ (`Full Offline Setup --with-nmt`):** علاوه بر برنامه و OCR آفلاین، مدل مترجم آفلاین ۶۰۰ میلیون پارامتری `NLLB-200` نیز داخل نصاب بسته‌بندی می‌شود تا هم OCR و هم ترجمهٔ فارسی/انگلیسی از لحظهٔ اول ۱۰۰٪ بدون اینترنت کار کنند.
- **حالت ۳ (`Full + wheelhouse`):** علاوه بر نصاب کامل، پوشهٔ `wheelhouse\` نیز برای نصب آفلاین با `start_windows.bat` دانلود و آماده می‌شود.
- **انتخاب پوشهٔ خروجی فایل `EXE` (نسخهٔ ۴.۲۹):** هنگام اجرای `build_windows_offline.bat` از شما پرسیده می‌شود فایل `EXE` و نصاب در کدام پوشه ساخته شوند (پیش‌فرض: `python_app\dist`)؛ می‌توانید همان مسیر را به‌صورت آرگومان دوم هم بدهید، مثلاً `build_windows_offline.bat --base "D:\ComicOCRStudioBuild"`. در حالت خط فرمانی، گزینه‌های `--output-dir` (پوشهٔ خروجی) و `--build-dir` (پوشهٔ موقت ساخت) هم در دسترس‌اند.
- **رفع مشکل نصب `PyInstaller` هنگام کندی یا مسدود بودن `pypi.org`:** اگر ساخت با پیام `Could not install PyInstaller` یا خطای `ReadTimeoutError` متوقف شد، سازندهٔ بسته اکنون ابتدا پوشهٔ `wheelhouse\` محلی، سپس `pypi.org` با مهلت ۱۲۰ ثانیه و ۱۰ بار تلاش مجدد و در نهایت میرورهای عمومی (`Aliyun PyPI` و `Tsinghua TUNA`) را امتحان می‌کند. اگر اینترنت ندارید، فایل `pyinstaller-*.whl` را در پوشهٔ `python_app\wheelhouse\` بگذارید تا ساخت کاملاً آفلاین انجام شود.
- **اطمینان از وجود مدل زبان فارسی داخل بستهٔ آفلاین (نسخهٔ ۴.۲۹):** سازندهٔ بسته پیش از ساخت، فایل‌های زبان `eng.traineddata` و `fas.traineddata` را بررسی می‌کند و اگر فایل فارسی نبود یا نسخهٔ کهنهٔ ۴۳۱ کیلوبایتی (`tessdata_fast`) بود، ساخت را با پیام روشن متوقف می‌کند؛ چون برنامهٔ ساخته‌شده بدون این فایل نمی‌تواند متن فارسی را بخواند و خطای `Tesseract language fas is not ready` می‌داد. برای ساخت آزادانه بدون این بررسی می‌توانید گزینهٔ `--allow-missing-language-models` را بدهید.

## اجرا

### ویندوز — ساده‌ترین روش

فایل **`start_windows.bat`** را دابل‌کلیک کنید. اگر محیط موجود قابل استفاده نباشد، راه‌انداز ابتدا Python ۶۴ بیتی سازگار (۳.۱۱ تا ۳.۱۳) را از launcher ویندوز، مسیرهای معمول و PATH پیدا می‌کند. اگر پیدا نشود، نصب‌کنندهٔ رسمی **Python 3.13.17 x64** را از python.org دریافت و SHA-256 آن را بررسی می‌کند؛ سپس آن را فقط برای کاربر فعلی نصب می‌کند، بدون تغییر PATH یا حذف نصب‌های دیگر. برای دانلود به PowerShell و اینترنت، و برای نصب به مجوز نوشتن در پوشهٔ کاربر و پوشهٔ برنامه نیاز است. ویندوز ۶۴ بیتی سازگار لازم است؛ نسخهٔ x64 است، نه نصب‌کنندهٔ بومی ARM. اگر دانلود/نصب خودکار ممکن نبود، Python ۶۴ بیتی ۳.۱۱ تا ۳.۱۳ را از [python.org](https://www.python.org/downloads/) نصب و فایل را دوباره اجرا کنید.

راه‌انداز `.venv` جداگانه می‌سازد، در صورت نیاز pip را با `ensurepip` ترمیم می‌کند و در هر اجرا pip، setuptools، wheel و بسته‌های موردنیاز برنامه و OCR پیش‌فرض را در محدودهٔ نسخه‌های سازگار بررسی و به‌روزرسانی می‌کند. نصب اولیه و دریافت به‌روزرسانی‌ها به اینترنت نیاز دارند. اگر به‌روزرسانی بسته‌ها ناموفق باشد، فقط در صورت وجود نصب موفق قبلی و موفق‌بودن بررسی وابستگی‌ها و import، برنامه با بسته‌های موجود اجرا می‌شود. برای جلوگیری از تغییر ناخواستهٔ برنامه‌های دیگر، Python سازگار موجود به‌صورت سراسری ارتقا نمی‌یابد و نسخهٔ ثابت نصب‌کننده نیز خودبه‌خود تغییر نمی‌کند؛ نصب یا ارتقای امنیتی Python موجود همچنان بر عهدهٔ شماست. Python 3.13.17 آخرین نصب‌کنندهٔ باینری شاخهٔ ۳.۱۳ هنگام این تغییر است، ولی نسخه‌های امنیتی جدیدترِ صرفاً source آن را جایگزین کرده‌اند.

اگر `.venv` خراب یا ناسازگار باشد، پس از یافتن Python مناسب به نام `.venv.previous-...` تغییر نام داده می‌شود و محیط جدید ساخته می‌شود؛ این پوشه و داده‌های پروژه پاک نمی‌شوند. بسته‌های OCR اختیاری که قبلاً در محیط قدیمی نصب شده‌اند باید در محیط جدید دوباره نصب شوند. اگر خطایی رخ دهد، متن خطا در پنجره باقی می‌ماند. این راه‌انداز قابلیت نصب موتورهای جداگانه مانند Tesseract یا دانلود خودکار مدل‌های اختیاری را ندارد؛ آن‌ها طبق راهنمای هر موتور و با انتخاب شما آماده می‌شوند.

#### نصب OCR با دسترسی مدیر در ویندوز

برای استفادهٔ عادی به Administrator نیاز نیست. اگر هنگام نصب بستهٔ OCR خطای **Access is denied / WinError 5** گرفتید، برنامه را ببندید و فایل **`start_windows_admin.bat`** را در همین پوشه اجرا کنید. ویندوز یک پیام UAC نشان می‌دهد؛ بعد از تأیید شما، همان launcher و برنامه با دسترسی مدیر باز می‌شوند و نصب OCR از پنجرهٔ «مدیریت مدل‌های OCR» نیز همین دسترسی را دارد. اگر برنامه قبلاً با دسترسی مدیر باز باشد، درخواست دوباره نمایش داده نمی‌شود.

این launcher به‌تنهایی مدل اختیاری دانلود نمی‌کند؛ آماده‌سازی و دانلود هر مدل همچنان فقط با کلیک شما انجام می‌شود. دسترسی مدیر برای خطای قطع اینترنت یا قفل‌شدن فایل توسط برنامهٔ دیگر راه‌حل نیست؛ در آن حالت متن خطای همان نصب را دنبال کنید.

### اجرای دستی

به Python 3.11 یا جدیدتر نیاز است. در همین پوشه:

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[ocr]'
.venv/bin/python run.py
```

در ویندوز، به‌جای `.venv/bin/...` از `.venv\\Scripts\\...` استفاده کنید. پس از نصب اولیه، وابستگی‌ها در پوشهٔ `python_app/.venv` می‌مانند؛ اجرای بعدی از همان محیط محلی استفاده می‌کند و دوباره بسته‌ها را نصب/به‌روزرسانی نمی‌کند. اگر `run.py` را با Python سراسری اجرا کنید، در صورت وجود `.venv` خودش به Python همان محیط منتقل می‌شود. راه‌انداز `start_windows.bat` نیز پس از آماده‌شدن محیط مستقیماً همان را اجرا می‌کند. نشانی پیش‌فرض `http://127.0.0.1:8765` است. فقط در نخستین اجرای تعاملی، برنامه به **انگلیسی** می‌پرسد کدام مرورگر (پیش‌فرض، Edge، Chrome یا Firefox) و کدام حالت بازشدن (زبانه در مرورگر باز یا پنجرهٔ جدید) را می‌خواهید. انتخاب در `browser-preferences.json` داخل پوشهٔ دادهٔ برنامه ذخیره می‌شود و اجراهای بعدی بدون سؤال از آن استفاده می‌کنند. برای تغییر انتخاب دائمی، این فایل را حذف کنید تا سؤال دوباره ظاهر شود؛ گزینه‌های دستی `--browser` و `--window` نیز برای همان اجرا اولویت دارند. اگر مرورگر انتخاب‌شده نصب نباشد، برنامه بی‌صدا به Edge برنمی‌گردد.

برای اجرای بدون سؤال می‌توانید انتخاب را از قبل بدهید:

```bash
.venv/bin/python run.py --browser firefox --window new
.venv/bin/python run.py --browser chrome --window existing
```

«همان مرورگرِ باز» یعنی درخواست زبانهٔ جدید به نمونهٔ در حال اجرای مرورگر؛ برنامه محتوای زبانه‌های فعلی شما را تغییر نمی‌دهد. در اجرای غیرتعاملی و بدون این گزینه‌ها، رفتار پیش‌فرض سیستم استفاده می‌شود.

اگر نمی‌خواهید مرورگر خودکار باز شود:

```bash
.venv/bin/python run.py --no-browser
```

اجرای بدون بستهٔ OCR هم ممکن است، اما برای استفاده از PP-OCR باید extra به نام `ocr` نصب شود. OpenCV headless جزو وابستگی‌های پایه است تا پیش‌پردازش‌های اختیاری OCR برای موتورهای دیگر نیز کار کنند؛ این بسته به‌تنهایی مدل OCR دانلود نمی‌کند. نصب بسته‌ها و آماده‌سازی مدل‌ها باید با انتخاب شما انجام شود. در ویندوز، راه‌انداز در هر اجرا وابستگی‌های پایه و OCR پیش‌فرض را بررسی و در صورت امکان به‌روزرسانی می‌کند.

## بک‌آپ و بازیابی پروژه

1. از **پروژه و تنظیمات** پروژهٔ موردنظر را باز کنید و ویرایش باز را ثبت کنید. «**بک‌آپ پروژه (ZIP)**» را بزنید و فایل دانلودشده را نگه دارید. اگر دانلود خودکار انجام نشد، پیوند «دانلود دوبارهٔ بک‌آپ» در همان منو باقی می‌ماند.
2. ZIP را به سیستم مقصد منتقل کنید. Comic OCR Studio نسخهٔ ۳.۴۱ یا جدیدتر را اجرا کنید و در همان منو «**بازیابی بک‌آپ**» را بزنید؛ فایل ZIP را انتخاب و تأیید کنید. بازیابی همیشه پروژه‌ای با شناسهٔ جدید می‌سازد و پروژه‌های موجود را حذف یا جایگزین نمی‌کند. می‌توانید به‌کار روی تصاویر و کادرها ادامه دهید.

فایل شامل اطلاعات و تنظیمات پروژه، همهٔ تصاویر اصلی صفحات و پیش‌نمایش‌های ذخیره‌شده، متن OCR و ترجمه، قالب‌بندی، موقعیت‌ها، گروه‌ها، برش، خلاصهٔ داستان و مراحل نیمه‌تمام ترجمه، خروجی‌های PDF/ZIP/TXT موجود در پوشهٔ پروژه و پیش‌نویس‌های ذخیره‌شدهٔ **همین مرورگر** برای کادرهای موجود است. در مقصد، پیش‌نویس‌ها در حافظهٔ مرورگر مقصد قرار می‌گیرند و هنگام بازکردن کادر برای بازیابی از شما سؤال می‌شود. اگر فضای حافظهٔ مرورگر کافی نباشد، پیام هشدار نمایش داده می‌شود و باید ZIP را نگه دارید.

به انتخاب شما، **کلیدهای API، تنظیمات سراسری حساب‌ها و فایل مدل‌های OCR در ZIP نیستند**؛ در سیستم جدید مدل لازم را آماده و کلیدها را جداگانه وارد کنید. خودِ PDF ورودی به‌صورت اصلی در پروژه نگهداری نمی‌شود؛ تصاویر صفحات واردشده پشتیبان‌گیری می‌شوند. تصویرهای پیوندشده با URL خارجی در HTML به‌شکل همان نشانی می‌مانند، نه فایل دانلودشده؛ تصاویر درج‌شده به‌صورت دادهٔ داخلی همراه متن ذخیره می‌شوند. ZIP رمزگذاری نشده است و متن‌ها و تصاویر خصوصی را در خود دارد؛ آن را مانند دادهٔ شخصی نگهداری کنید.

حجم بازشدهٔ مجاز بک‌آپ حداکثر ۱۰ گیگابایت، خود ZIP حداکثر ۵ گیگابایت و تعداد فایل‌ها حداکثر ۱۰٬۰۰۰ است. برای امنیت، ساختار ZIP، تصاویر، مسیرها، اندازه و نسخه پیش از انتشار پروژهٔ بازیابی‌شده بررسی می‌شوند؛ فایل نامعتبر پروژهٔ جدید نمی‌سازد.

## امکانات

- ورود چند فایل تصویری یا PDF؛ صفحات PDF به تصویرهای قابل ویرایش تبدیل می‌شوند.
- پروژه‌های ذخیره‌شونده روی کامپیوتر، انتخاب همه/هیچ/معکوس و انتخاب محدوده با Shift، ترتیب دستی و کشیدن کارت‌ها، کپی و حذف؛ حذف پروژه نیز از منوی پروژه ممکن است.
- مدیریت کامل گروه‌ها: ساخت و ادغام، شماره و رنگ، کادر دور اعضا، انتخاب گروه، ویرایش عضوها، لغو گروه، جابه‌جایی گروه به‌صورت یک بلوک و مرتب‌سازی داخل گروه. رهاکردن روی وسط کارت گروه می‌سازد، رهاکردن نزدیک لبه جابه‌جا می‌کند و رهاکردن عضو در فضای خالی او را از گروه خارج می‌کند.
- رابط تیره/روشن با چیدمان، کارت‌ها و نوار خروجی مشابه افزونه؛ نام و تنظیمات پروژه خودکار ذخیره می‌شوند.
- پیش‌نمایش صفحهٔ اصلی هنگام بازکردن پروژه و بعد از ترجمه/ویرایش از آخرین متن ساخته می‌شود؛ یک رندر قدیمی‌تر نمی‌تواند نسخهٔ تازه را جایگزین کند.
- بعد از ساخت PDF، ZIP یا TXT، پیوند «دانلود» در بخش وضعیت باقی می‌ماند؛ اگر دانلود خودکار مرورگر انجام نشد، همان فایل با این پیوند قابل دریافت است.
- OCR محلی با PP-OCRv6 Small؛ PP-OCRv5 Multilingual و EasyOCR به‌عنوان گزینهٔ جداگانه.
- اگر OCR اصلی خالی، خیلی کوتاه یا کم‌اطمینان باشد، یک تلاش اختیاری با بزرگ‌نمایی ۳×، جداسازی پیکسل‌های بسیار روشن و معکوس‌کردن رنگ انجام می‌شود؛ نتیجه فقط وقتی بهتر است جایگزین می‌شود.
- مسیر اختیاری «پیش‌پردازش حباب» نیز فقط بعد از ضعیف‌بودن OCR اصلی اجرا می‌شود: کانتور تیره با `MORPH_CLOSE 25×25` و حداقل مساحت 8000، mask با erode به اندازهٔ 15، میانه و یکدستی پس‌زمینه 55٪ در بازهٔ ±20، استخراج جوهر با ضریب 0.45، بزرگ‌نمایی ۳× و حاشیهٔ سفید 30 پیکسل. نواحی با میانگین confidence کلمات زیر 60 حذف می‌شوند، حباب‌ها از بالا به پایین خوانده می‌شوند و برای Tesseract از `--psm 6` استفاده می‌شود. بهترین نتیجه در میان OCR اصلی و fallbackها انتخاب می‌شود؛ همهٔ آستانه‌ها در ابتدای `ocr.py` قابل تنظیم‌اند.
- پس از OCR، گزینهٔ پیش‌فرض «ادغام خودکار خط‌های نزدیک در یک کادر حباب» خط‌های نزدیک با هم‌پوشانی افقی را به یک متن و کادر تبدیل می‌کند؛ مثلاً `WHY ARE YOU` و `RUNNING AROUND` به `WHY ARE YOU RUNNING AROUND` تبدیل می‌شوند. تشخیص تنها بر اساس موقعیت است و همیشه مرز واقعی حباب را نمی‌فهمد؛ می‌توان گزینه را خاموش کرد. در ویرایشگر با Ctrl/⌘ و کلیک چند کادر را انتخاب کنید و «ادغام متن‌ها» را بزنید، یا یک کادر ادغام‌شده را انتخاب و «جداکردن خط‌ها» را بزنید. خط‌ها و مختصات اصلی ذخیره می‌شوند. برای جلوگیری از ازدست‌رفتن ترجمه و ویرایش، ادغام دستی فقط پیش از ترجمه و جداسازی پیش از ترجمه و تغییر متن ادغام‌شده مجاز است. پروژه‌های قبلی تا اجرای دوبارهٔ OCR یا ادغام دستی خودبه‌خود تغییر نمی‌کنند.
- آزمایش موتور روی نخستین تصویر انتخاب‌شده بدون تغییر دادن پروژه.
- کلیک روی تصویر یا کارت و یک کلیک روی کادر تیک، انتخاب را تغییر می‌دهد؛ حتی بعد از ذخیرهٔ خودکار نیازی به دو کلیک نیست. دکمهٔ چشم فقط پیش‌نمایش را باز می‌کند و تصویرهای انتخاب‌نشده کمی خاکستری و کم‌نور می‌شوند تا وضعیتشان روشن باشد.
- کارت‌های مدل زیر هم نمایش داده می‌شوند؛ Escape پنجرهٔ باز را می‌بندد و سربرگ پنجره‌ها هنگام اسکرول در دسترس می‌ماند.
- بخش «گزارش زندهٔ کارها» مراحل ورود فایل، نصب/دانلود مدل، OCR، ترجمه و خروجی را همان لحظه نشان می‌دهد. بعد از OCR، متن واقعی خوانده‌شدهٔ هر تصویر نیز خط‌به‌خط در گزارش می‌آید؛ پیام موفق با علامت سبز و متن خوانا نمایش داده می‌شود.
- در اجرای معمولی با `run.py` یا راه‌انداز ویندوز، بستن آخرین زبانهٔ برنامه پس از مهلت کوتاه سرور Python را خاموش می‌کند. heartbeat جلوی خاموش‌شدن هنگام refresh یا بازبودن زبانهٔ دیگر را می‌گیرد.
- پیش از ترجمهٔ AI، متن دقیق درخواست اول، دستور سیستم، مقصد، اسکیل و خلاصه در پنجره نشان داده می‌شوند. درخواست‌های بعدی پس از تولید خلاصه ساخته می‌شوند و با همان تأیید به‌ترتیب ارسال می‌شوند؛ متن دقیق آینده پیش از دریافت پاسخ قبلی قابل نمایش نیست و هنگام ارسال در گزارش زنده (بدون هدر کلید) نشان داده می‌شود. گزارش حاوی متن و خلاصهٔ خصوصی است. تغییر تنظیمات یا پروژه پیش از ارسال بررسی می‌شود. حالت رایگان همچنان پیش‌نمایش درخواست‌های خود را دارد.
- ترجمهٔ رایگان: Google Translate ابتدا و پس از خطا MyMemory امتحان می‌شود. کادرهای **همان صفحه** تا سقف با خط جدید تجمیع و ترتیبی ترجمه می‌شوند؛ در صورت امکان، یک بخش کامل از کادر بعدی هم برای پرکردن ظرفیت استفاده می‌شود. صفحه‌ها هرگز ترکیب نمی‌شوند. اگر ادغام بدون عبور از سقف، جابه‌جایی ترتیب یا شکستن خط/جمله ممکن نباشد، درخواست کوتاه مستقل اجتناب‌ناپذیر است. پاسخ چندکادری باید تعداد خطوط و جای خط‌های خالی را حفظ کند؛ ناسازگاری خطا می‌دهد و ذخیره نمی‌شود. شمارش خطوط درستی معنایی را تضمین نمی‌کند.
- در تنظیمات هر دو سرویس رایگان، زمان انتظار، تعداد تکرار، فاصله و سقف نویسه جداگانه قابل تغییر است؛ پیش‌فرض زمان ۹۰ ثانیه، تکرار اضافی صفر، فاصله ۲۰ ثانیه و سقف Google برابر ۱۰۰۰ و MyMemory برابر ۵۰۰ نویسه است. برای امن‌بودن مسیر جایگزین، سقف مؤثر کمترین سقف دو سرویس است و **تمام درخواست‌ها حداکثر ۵۰۰ بایت UTF-8** دارند (محدودیت [مستند MyMemory](https://mymemory.translated.net/doc/spec.php)). این محدودیت ۵۰۰ بایتی، محدودیت ادعایی Google نیست و برای متن چندبایتی زودتر از سقف نویسه پر می‌شود. سهمیه‌ها و دسترسی سرویس‌ها ممکن است تغییر کنند. اگر خط کامل در سقف جا نشود و مرز امن وجود نداشته باشد، پیش از ارسال خطا داده می‌شود و باید متن را اصلاح کرد.
- پیش‌نمایش رایگان، دقیقاً درخواست اول و سیاست خودکار درخواست‌های بعدی را نشان می‌دهد؛ تأیید یک‌باره است و متن واقعی هر ارسال در گزارش ثبت می‌شود. تکرار خودکار به تنظیمات هر سرویس وابسته است؛ بعد از پایان تلاش‌های Google همان متن پس از فاصلهٔ تعیین‌شده به MyMemory فرستاده می‌شود. در صورت خطا، درخواست‌های موفق ذخیره می‌مانند و می‌توان درخواست ناموفق را دوباره امتحان کرد یا خطا را کپی و بعداً ادامه داد. وضعیت درخواست قطع‌شده ممکن است نامعلوم و ارسال مجدد تکراری باشد. استفادهٔ مجدد از متن‌های یکسان برای رایگان و AI قابل خاموش‌کردن است؛ بافت متفاوت ممکن است ترجمهٔ متفاوت بخواهد. جایگزین‌کردن نوبت ناتمام نیاز به تأیید صریح دارد. بازترجمهٔ یک کادر پس از اتمام همهٔ بخش‌ها ذخیره می‌شود و تلاش دوبارهٔ آن از ابتداست. رایگان هیچ اسکیل یا خلاصهٔ AI ندارد.
- AI از **Google Gemini، OpenAI، OpenRouter و AvalAI** پشتیبانی می‌کند. هر درخواست فقط متن کادرهای یک صفحه و خلاصهٔ کوتاه مراحل قبلی را دارد؛ تصویر و نام فایل جداگانه فرستاده نمی‌شوند. جمع متن پیام سیستم و پیام کاربر حداکثر سقف فعال API است، پیش‌فرض ۱۰۰۰ نویسه؛ این شمارش شامل دستور، راهنما، خلاصه، برچسب‌ها و OCR است، نه JSON انتقال، توکن سرویس یا پاسخ تولیدشده. پس از پاسخ معتبر، ترجمه و خلاصه با هم ذخیره می‌شوند و ظرفیت بعدی با طول واقعی خلاصه دوباره محاسبه می‌شود. تکه‌های یک کادر بلند تا تکمیل آن محفوظ و ترجمهٔ قدیمی دست‌نخورده می‌ماند. تقسیم کادر بلند فقط در پایان خط دارای نشانهٔ پایان جمله یا مرز بند است؛ مرز خطوط OCR ادغام‌شده فقط بعد از تطابق دقیق استفاده می‌شود. اگر خطی در فضای ممکن جا نشود، برنامه پیش از ارسال آن درخواست متوقف می‌شود. حافظه و کنترل تعداد خطوط به‌تنهایی دقت معنایی یا جلوگیری از timeout را تضمین نمی‌کنند.
- شمارش خطوط نمی‌تواند جابه‌جایی معنایی خط‌ها توسط مترجم را تشخیص دهد؛ پس از ترجمه، ترتیب و محتوای کادرها را بازبینی کنید. اگر پروژه هنگام OCR، ترجمه یا ورود فایل در جای دیگری تغییر کند، نتیجه برای جلوگیری از بازنویسی ذخیره نمی‌شود و باید دوباره تلاش کنید.
- بعد از OCR متن اصلی و بعد از ترجمه، متن ترجمه روی تصویر قرار می‌گیرد. انتخابگرهای «متن روی تصویر» سه حالت «ترجمه»، «متن اصلی OCR» و «بدون متن» دارند و پیش‌نمایش را بلافاصله بازسازی می‌کنند. «بدون متن» تصویر اصلی را برای پیش‌نمایش و PDF/ZIP برمی‌گرداند، اما OCR و ترجمهٔ ذخیره‌شده پاک نمی‌شوند؛ پروژه‌های قبلی به‌صورت پیش‌فرض در حالت ترجمه می‌مانند.
- ویرایش مستقیم داخل کادر تصویر برای متن OCR و ترجمه، با ابزار بالای همان کادر، با قالب‌بندی غنی، فهرست، خط‌خورده، واگرد/ازنو، راست‌به‌چپ/چپ‌به‌راست و تراز راست، وسط، چپ و **جاستیفای**. در جاستیفای، خط‌هایی که خودکار شکسته‌اند از دو طرف تراز می‌شوند؛ خط آخر و خطِ پیش از شکست دستی کشیده نمی‌شوند. نشانگر فهرست نیز در تصویر رندر می‌شود.
- با کلیک روی متن یا کادر خالی تصویر، ویرایش داخل همان کادر فعال و نوار ابزار بالای آن نمایش داده می‌شود؛ کادر متنی جداگانه باز نمی‌شود. هر Enter خط/پاراگراف مستقلی می‌سازد؛ نشانگر را روی خط بگذارید؛ تراز و جهت همان خط از نوار ابزار و اندازهٔ خط از کنترل «اندازهٔ خط روی تصویر» تنظیم می‌شوند. رنگ با انتخاب متن یا گذاشتن نشانگر روی خط اعمال می‌شود. خطی که فقط به‌علت عرض کادر خودکار شکسته می‌شود، همچنان بخشی از همان پاراگراف است. تنظیمات مستقل در پیش‌نمایش، ذخیره و خروجی تصویر/PDF حفظ می‌شوند؛ اندازه فقط بر تصویر اثر دارد، نه اندازهٔ نوشتهٔ کادر ویرایش.
- تغییر متن و تنظیمات ابتدا در پیش‌نویس می‌مانند؛ «ثبت» نتیجه را در همان تصویر به‌روزرسانی می‌کند و با لغو می‌توان تغییرها را کنار گذاشت. در صورت کمبود فضا، محیط تصویر برای نمایش ابزارهای بالای کادر جابه‌جا می‌شود. کارت کناری فقط نمایش و کنترل دارد و دکمهٔ ویرایش آن همان ویرایشگر را باز می‌کند؛ ابزارهای گروهی همچنان در دسترس‌اند. ویرایشگر با JavaScript بومی و شبیه ظاهر و ابزار ویرایشگر کلاسیک وردپرس ساخته شده است، نه با خود وردپرس یا TinyMCE.
- در نوار بالای کادر، «جای عمودی متن در کادر» را روی بالا، وسط یا پایین بگذارید؛ انتخاب برای OCR و ترجمهٔ همان کادر مشترک است و در پیش‌نمایش، PDF و ZIP اعمال و در پروژه ذخیره می‌شود. برای حفظ ظاهر پروژه‌های قبلی، کادرهای بدون این تنظیم مثل گذشته وسط‌چین عمودی می‌مانند. زمینهٔ تیره و اندازهٔ ثابت متن ویرایش برای خوانایی و ثبات نشانگر حفظ شده‌اند؛ ضخامت، جهت و تراز تا حد امکان با متن خروجی هماهنگ‌اند. اندازه و خط‌شکنی مرورگر می‌توانند متفاوت باشند؛ «پیش‌نمایش دقیق» پیش‌نویس ثبت‌نشده را با رندر واقعی خروجی نشان می‌دهد و «ادامهٔ ویرایش» آن را برمی‌گرداند. ثبت و لغو همچنان جدا هستند.
- ابزار فقط با انتخاب کادر ظاهر می‌شود. کلیک روی فضای خالی تصویر آن را پنهان می‌کند؛ اگر پیش‌نویس تغییر کرده باشد، پیش از کنارگذاشتنش تأیید گرفته می‌شود. کشیدن تصویر برای جابه‌جایی آن پیش‌نویس را نمی‌بندد.
- اندازه و رنگ پیش‌فرض هر کادر در بخش جمع‌شوندهٔ تنظیمات کل کادر به تصویر و خروجی مربوط‌اند؛ مقدار خالی اندازه و گزینهٔ رنگ خودکار تنظیمات پیش‌فرض را برمی‌گردانند. اندازهٔ دستی بزرگ ممکن است از ارتفاع کادر بیشتر و در لبهٔ آن بریده شود؛ در این صورت کادر را بزرگ‌تر یا اندازه را کمتر کنید.
- تب‌های Visual و Text، دو ردیف ابزار، درج پیوند/تصویر/جدول، میانبرهای Ctrl+B/I/U/K/Z/Y و چسباندن HTML پاک‌سازی‌شده یا متن ساده در ویرایشگر ترجمه وجود دارند. OCR همچنان متن ساده است. ویرایشگر فقط زیرمجموعه‌ای از HTML و CSS امن را نگه می‌دارد؛ تگ‌ها و ویژگی‌های ناشناخته، اسکریپت و نشانی خطرناک حذف می‌شوند. آپلود تصویر به PNG/JPEG/GIF/WebP و حداکثر ۲ مگابایت محدود است.
- متن و تنظیمات پیش‌نویس هر چند ثانیه در `localStorage` همان مرورگر، جداگانه برای پروژه/تصویر/کادر/زبان ذخیره و در بازگشت با اجازهٔ کاربر بازیابی می‌شود؛ ذخیرهٔ محلی جایگزین «ثبت» و ذخیرهٔ پروژه نیست. لغو یا ثبت پیش‌نویس آن را پاک می‌کند؛ پاک‌کردن دادهٔ مرورگر، حالت خصوصی یا محدودیت فضای ذخیره‌سازی ممکن است بازیابی را ناممکن کند.
- **محدودیت خروجی:** HTML امن تصویر، جدول و پیوند در پروژه می‌ماند و در ویرایشگر قابل استفاده است؛ ولی خروجی تصویر/ZIP/PDF رندر صفحهٔ وب نیست: تصویر فقط با متن جایگزین، جدول به‌صورت متن جداشده، تیتر/نقل‌قول/تورفتگی به‌صورت ساده و جداکننده/Read More با نشانهٔ متنی نمایش داده می‌شوند. پیوند در تصویر کلیک‌پذیر نیست. پیش از ثبت چنین محتوایی هشدار و تأیید نمایش داده می‌شود. خروجی TXT متن است، نه HTML. برای چیدمان کامل WordPress از خروجی این برنامه استفاده نکنید.
- «تمام‌صفحه تصویر» کنار کنترل‌های زوم، کل تصویر را هم از نظر عرض و هم ارتفاع در نما جا می‌دهد؛ بزرگ‌نمایی دستی و خروج با دکمه یا Escape در دسترس‌اند. پیش‌نویس، انتخاب و زوم قبلی پس از خروج حفظ می‌شوند. اگر مرورگر داخل قاب اجازهٔ تمام‌صفحه ندهد، نما در فضای همان قاب بزرگ می‌شود.
- متن زیر لایهٔ ویرایش با همان `Typeset.render` خروجی و به‌ترتیب «همهٔ پاک‌سازی‌ها، همهٔ پس‌زمینه‌ها، سپس همهٔ متن‌ها» ساخته می‌شود؛ بنابراین پس از ثبت و هنگام کشیدن، هم‌پوشانی واقعی دیده می‌شود و پس‌زمینهٔ کادر بعدی متن قبلی را نمی‌پوشاند.
- زبان نمایش هر متن مستقل است: با دکمهٔ فا/EN روی کادر یا انتخابگر «نمایش همین متن» در کارتش می‌توان فقط همان متن را «فارسی / ترجمه» یا «انگلیسی / OCR» کرد. انتخاب‌ها ذخیره می‌شوند و در پیش‌نمایش و PDF/ZIP می‌توان بعضی کادرها فارسی و بعضی انگلیسی باشند. انتخاب کلی، پیش‌فرض متن‌های بدون انتخاب جداگانه است و «بدون متن» همچنان همه را پنهان می‌کند.
- نمایش/عدم‌نمایش هر خط مستقل از خطوط دیگر است: دکمهٔ 👁 روی همان کادر آن را پنهان می‌کند و تیک «نمایش متن … روی تصویر» در کارت همان خط، آن را پنهان یا دوباره نمایان می‌کند. این انتخاب در پیش‌نمایش و PDF/ZIP حفظ می‌شود و متن OCR یا ترجمهٔ خط پنهان حذف نمی‌شود.
- جابه‌جایی و تغییر اندازهٔ کادر ترجمه با هشت دستگیره، برش تصویر با هشت دستگیره و نسبت‌های ثابت، پیش‌نمایش برش‌خورده و کپی تصویر.
- انتخاب چند متن با Ctrl/⌘ + کلیک یا «انتخاب همه»؛ **اولین کادر انتخاب‌شده مرجع است** و دکمهٔ «هم‌اندازه با اولی» عرض و ارتفاع همهٔ کادرهای دیگر را، حتی با بیش از دو انتخاب، از آن کپی می‌کند. کادر مرجع در این عمل ثابت می‌ماند، مرکز هر هدف تا جای ممکن حفظ و کادر داخل مرز تصویر نگه داشته می‌شود. تراز گروهی چپ، وسط افقی، راست، بالا، وسط عمودی و پایین و جابه‌جایی گروهی با ⠿ نیز موجود است؛ مختصات ناحیهٔ پاک‌سازی OCR تغییر نمی‌کند و نتیجه به پیش‌نمایش و PDF/ZIP می‌رسد.
- خروجی PDF معمولی، قاب‌های هم‌اندازه، دو تصویر در صفحه و حالت seamless؛ اعضای هر گروه با حفظ نسبت ابعاد و یکسان‌سازی عرض، به‌صورت عمودی به یک صفحه تبدیل می‌شوند و در حالت دو-تصویر، گروه از هم نمی‌شکند. خروجی ZIP با فرمت اصلی/PNG/JPEG و خروجی متنی با تورفتگی نیز موجود است.

### OCR و تشخیص خطای ترجمه

اگر هنگام زدن ترجمه، تصویر انتخاب‌شده‌ای هنوز کادر OCR ندارد و OCR موفقی برایش ثبت نشده، پنجرهٔ OCR باز می‌شود؛ موتور و زبان را بررسی کنید و «شروع OCR» را بزنید. فقط تصاویر بدون OCR خوانده می‌شوند و کادرها و ویرایش‌های موجود بازنویسی نمی‌شوند. پس از OCR، پیش‌نمایش معمول باز می‌شود و ارسال همچنان به تأیید شما نیاز دارد. بستن پنجره یا خطای OCR ترجمه را ارسال نمی‌کند. پروژه‌های قدیمیِ بدون کادر ممکن است یک بار OCR لازم داشته باشند. اگر OCR موفق باشد اما متنی نیابد، خطا اعلام می‌شود و چرخهٔ تکرار خودکار رخ نمی‌دهد؛ می‌توانید OCR را از پنل خودش با تنظیمات دیگر دوباره اجرا کنید. صفحهٔ بدون متن فعال در مجموعهٔ ترکیبی از ترجمه کنار گذاشته می‌شود. OCR جدید ممکن است با نوبت ترجمهٔ ناتمام ناسازگار باشد؛ قبل از جایگزینی پیشرفت، تأیید گرفته می‌شود.

خطاهای آماده‌سازی، اتصال، HTTP، پیش‌نمایش و OCR در پنجره می‌مانند و دکمهٔ کپی دارند. خطای داخلی پیش‌بینی‌نشده شناسه، نوع خطا و محل کد را نیز نشان می‌دهد؛ محتوای درخواست عمداً جمع‌آوری نمی‌شود، اما متن خود خطا می‌تواند حاوی اطلاعات شخصی باشد. پیش از فرستادن گزارش، آن را بررسی کنید؛ حذف همهٔ اطلاعات حساس تضمین نمی‌شود. در قطع شبکه یا timeout وضعیت پردازش درخواست ترجمه ممکن است نامعلوم باشد و تکرار هزینهٔ دوباره داشته باشد. ذخیرهٔ موفق تنظیمات پنجره را می‌بندد؛ خطا آن را باز نگه می‌دارد. تست کلید که به‌طور داخلی تنظیمات را ذخیره می‌کند پنجره را نمی‌بندد.

### راهنمای ترجمهٔ AI برای هر نوبت

پیش از ترجمهٔ AI می‌توانید اسکیل و خلاصهٔ قبلی را مشاهده و ویرایش کنید. تغییر آن‌ها ابتدا پیش‌نمایش محلی تازه می‌سازد؛ تأیید نهایی درخواست اول و سیاست ساخت خودکار درخواست‌های بعدی را می‌پذیرد. اسکیل در همهٔ درخواست‌های نوبت ثابت است و خلاصه پس از هر پاسخ به‌روز می‌شود. در اولین نوبت خلاصه خالی است. خلاصهٔ باقی‌مانده از نوبت قبلی در شروع نوبت جدید قابل پاک‌کردن یا ویرایش است. ترجمهٔ رایگان از این حافظه استفاده نمی‌کند.

سقف اسکیل و خلاصه هر دو پیش‌فرض ۱۵٪ از سقف کل‌اند و در تنظیمات قابل تغییرند؛ جمع درصدها حداکثر ۱۰۰ است. مقدار استفاده‌نشده به متن اصلی می‌رسد و اسکیل ذخیره‌شدهٔ بیش‌ازحد بدون کوتاه‌شدن نمایش داده می‌شود تا قبل از ارسال اصلاح شود. هر پاسخ باید JSON معتبر با ترجمه و خلاصهٔ یک‌خطی در سقف تعیین‌شده داشته باشد؛ خروجی نامعتبر پذیرفته نمی‌شود و ممکن است تکرار هزینه داشته باشد. خلاصه ممکن است اشتباه باشد: پیش از شروع نوبت آن را ببینید و اصلاح کنید. راهنمای تأییدشده در localStorage جدا برای هر پروژه و خارج از ZIP است، ولی خلاصه و پیشرفت در فایل پروژه و ZIP قرار دارند. اطلاعات محرمانه در هیچ‌کدام وارد نکنید. بازترجمهٔ تکی خلاصه را به‌عنوان زمینه می‌خواند اما خلاصهٔ تازهٔ آن را در حافظهٔ اصلی داستان ذخیره نمی‌کند.

پیشرفت ناتمامِ قالب قدیمی ۳.۴۷ با حافظهٔ جدید سازگار نیست: برنامه قبل از کنارگذاشتن آن و شروع دوباره از شما تأیید می‌گیرد. برای حفظ پیشرفت قبلی می‌توانید پیش از ارتقا آن را با نسخهٔ قبلی کامل کنید. APIهای قدیمی AI برای استفادهٔ مستقیم همچنان روش و سقف پیشین را دارند؛ مسیرهای رایگان قدیمی نیز به برنامه‌ریز جدید وصل شده‌اند. تأیید در APIهای قدیمی اختیاری است، اما رابط برنامه همواره تأیید می‌خواهد.

### پاسخ نامعتبر AI و اصلاح بدون درخواست دوباره

پاسخ JSON خالص، داخل fence یا همراه توضیح بیرونی در صورت وجود یک شیء JSON بدون ابهام پذیرفته می‌شود. دو پاسخ، کلید تکراری یا ناهماهنگی خط‌ها ذخیره نمی‌شوند. اگر پاسخ از نظر JSON/ساختار یا تعداد خطوط نامعتبر باشد، برنامه به تعداد «تکرار اضافی» تنظیم‌شده همان API را با فاصلهٔ ثبت‌شده امتحان می‌کند و هر بار در گزارش زنده اعلام می‌کند؛ هر تلاش ممکن است هزینه داشته باشد. در پایان تکرارها یا وقتی تعداد تکرار صفر است، پاسخ آخر برای اصلاح محلی نگه داشته می‌شود؛ به کلید بعدی خودکار نمی‌رود و پاسخ را بی‌اجازه دوباره نمی‌فرستد. برای کادرهای متعدد، ترجمه‌ها باید به ترتیب و هرکدام در خط جدا باشند. پس از ثبت موفق، درخواست‌های بعدی نوبت با تأیید قبلی ادامه پیدا می‌کنند. دکمهٔ «تلاش دوباره» یک درخواست جدید است و ممکن است هزینه داشته باشد.

پاسخ خام در گزارش خطا، فایل پروژه و بک‌آپ ذخیره نمی‌شود، اما می‌تواند اطلاعات خصوصی یا اسرار تکرارشده توسط مدل داشته باشد؛ هنگام نمایش، کپی یا اشتراک مراقب باشید. فرصت اصلاح فقط در حافظهٔ برنامه تا ۳۰ دقیقه، و تا بسته‌شدن پنجره در رابط باقی می‌ماند؛ پس از خروج، راه‌اندازی مجدد یا تغییر پروژه/تنظیمات ممکن است بازیابی ممکن نباشد. با تغییر پروژه یا مقصد، برنامه اجازهٔ بازنویسی بر اساس پاسخ قدیمی را نمی‌دهد. حداکثر ۲۰۰٬۰۰۰ نویسه از پاسخ خام نمایش داده می‌شود. پاسخ‌های بزرگ‌تر کوتاه نمایش داده و اعلام می‌شوند. این رفتار برای مسیر فعلی AI پروژه و بازترجمهٔ تکی است؛ APIهای قدیمی مستقیم AI روش قدیمی خود را دارند.

در تنظیم «قالب پاسخ AI»، حالت خودکار برای نشانی رسمی OpenAI و Gemini حالت JSON سرویس را درخواست می‌کند؛ برای نشانی سفارشی و دیگر سرویس‌ها پیش‌فرض بدون اجبار است. برای هر سرویس می‌توان حالت JSON یا متن معمولی را دستی انتخاب کرد. اگر مدل حالت JSON را رد کند، متن خطا را ببینید و پس از بررسی حالت متن معمولی را انتخاب کنید؛ برنامه خودکار با حالت دیگر دوباره ارسال نمی‌کند. حالت JSON صحت ترجمه، خطوط یا خلاصه را تضمین نمی‌کند.

### تنظیم و تست اتصال هوش مصنوعی

1. از «پروژه و تنظیمات ← مدیریت ترجمه‌ها» سرویس را انتخاب کنید. نام مدل باید دقیقاً همان شناسهٔ موجود در همان سرویس باشد؛ برنامه مدل دیگری را جایگزین آن نمی‌کند.
2. برای هر کلید یک نام دلخواه و خود کلید را وارد کنید. با «افزودن API» می‌توانید کلیدهای بیشتری برای همان سرویس بسازید و با × ردیف اضافی را حذف کنید.
3. برای هر ردیف **زمان انتظار** (۵ تا ۶۰۰ ثانیه، پیش‌فرض ۹۰)، **تکرار اضافی** (۰ تا ۵، پیش‌فرض ۰)، **فاصلهٔ تلاش مجدد** (۰ تا ۳۰۰ ثانیه، پیش‌فرض ۲۰) و **سقف کل نویسهٔ پیام‌ها** (۱ تا ۱۰۰۰۰۰، پیش‌فرض ۱۰۰۰) را جداگانه تنظیم کنید. کمترین سقف کلیدهای فعال مبنای همهٔ درخواست‌های آن سرویس است. این سقف جمع نویسه‌های محتوای پیام سیستم و کاربر است، نه محدودیت توکن یا کل بدنهٔ JSON سرویس. صفر در تعداد تکرار یعنی یک تلاش اولیه. زمان انتظار سقف هر مرحلهٔ شبکه است، نه الزاماً کل زمان درخواست.
4. «تست» همان ردیف ابتدا تنظیمات را ذخیره می‌کند و سپس فقط مشخصات/فهرست مدل را می‌خواند. متن کمیک ارسال نمی‌شود؛ موفقیت یعنی مدل در فهرست پاسخ وجود دارد، نه تضمین موفقیت ترجمه.
5. «ذخیره» را بزنید و ترجمه را اجرا کنید. در خطای ارتباطی و HTTP 408/429/5xx، همان کلید به تعداد تکرار تنظیم‌شده و با فاصلهٔ انتخاب‌شده دوباره امتحان می‌شود. هنگام رفتن به کلید بعدی هم فاصلهٔ کلید ناموفق اعمال می‌شود؛ این فاصله محدودیت اعلام‌شدهٔ سرویس را خودکار تشخیص نمی‌دهد. ۴۰۱/۴۰۳ و خطاهای مشابه با همان کلید تکرار نمی‌شوند؛ ممکن است کلید بعدی سرویس امتحان شود. در قطع ارتباط بعد از اتمام تکرارهای همان کلید، کلید بعدی امتحان نمی‌شود. در برخی خطاهای HTTP، رفتن به کلید بعدی نیز درخواست جدید است، حتی وقتی تکرار صفر است؛ پاسخ نامعتبر AI فقط به تعداد تکرارِ صریحاً تنظیم‌شده روی همان API دوباره فرستاده می‌شود و پس از پایان آن، برای اصلاح محلی نگه داشته می‌شود. **هر تکرار یا استفاده از کلید بعدی ممکن است باعث مصرف یا هزینهٔ دوباره شود.** تعداد درخواست پیش‌نمایش، تکرارهای احتمالی را شامل نمی‌شود.
6. پس از توقف ترجمه، پنجره خطا و انتخاب «تلاش دوباره» یا «کپی خطا و پایان» را نشان می‌دهد؛ تلاش دوباره از درخواست ناموفق ادامه می‌دهد و درخواست‌های موفق همان اجرا را دوباره نمی‌فرستد. در تعارض ویرایش/تأیید یا اشکال بازسازی پیش‌نمایش، به‌جای تکرار کور باید مشکل را رفع و پیش‌نمایش تازه گرفت. اگر کپی ناموفق باشد، پنجره باز می‌ماند تا متن دستی کپی شود. بازترجمهٔ جداگانهٔ یک کادر ممکن است با تلاش دوباره از بخش اول شروع شود. پیام خطا همراه نوع خطای شبکه یا کد HTTP واقعی و پیام قابل‌دریافت سرویس در پنجره و گزارش فعالیت می‌ماند. کلیدهای شناخته‌شده و اطلاعات رایج احراز هویت پوشانده می‌شوند؛ بااین‌حال ممکن است سرویس اطلاعات دیگری در متن خطا بفرستد، پس قبل از اشتراک آن را بازبینی کنید. بدنهٔ HTML کامل و هدرهای حساس نمایش داده نمی‌شوند و متن جزئیات طولانی کوتاه می‌شود.

گزینهٔ **استفادهٔ مجدد از ترجمهٔ کادرهای دقیقاً یکسان** پیش‌فرض روشن و قابل خاموش‌کردن است. در یک نوبت، نخستین کادر فعال با متن یکسان ترجمه می‌شود و نتیجه به همهٔ نسخه‌های انتخاب‌شده اعمال می‌شود؛ متن مشابه ولی متفاوت تطبیق داده نمی‌شود. در ادامهٔ همان نوبت، نتیجهٔ ذخیره‌شده دوباره فرستاده نمی‌شود، اما شروع نوبت جدید می‌تواند متن را دوباره ترجمه کند. متن یکسان در بافت‌های مختلف ممکن است ترجمهٔ متفاوتی بخواهد؛ در آن حالت این گزینه را خاموش کنید.

کلید ذخیره‌شده به مرورگر برگردانده نمی‌شود؛ فیلد خالی بعد از ذخیره یعنی همان کلید قبلی حفظ شده است. تنظیمات قدیمی تک‌کلیدی AvalAI/OpenAI هنگام خواندن به فضای سرویس متناسب منتقل می‌شوند. برای OpenAI و سرویس محلی سازگار می‌توانید «نشانی پایهٔ API» را تغییر دهید؛ برای Gemini، OpenRouter و AvalAI نیز نشانی پیش‌فرض رسمی همان سرویس استفاده می‌شود.

### مسیر اختیاری آماده‌سازی متن برای ترجمه

ماژول `comic_studio.text_preparation` یک مسیر **جدید و opt-in** برای ساخت واحدهای ترجمه است؛ مسیر فعال فعلی برنامه، امضای `TranslationService.translate()`، ساختار OCR و API پروژه را تغییر نمی‌دهد. تابع `prepare_translation_units(lines, mode=...)` با `bubble` خطوط هر ناحیه را از بالا به پایین به حباب‌های جدا تبدیل می‌کند و با `document` پاراگراف‌ها و واحدهای خاص را جدا نگه می‌دارد. نوع واحد سند با `kind` روی خط مشخص می‌شود: `heading`، `list_item`، `table_cell`، `formula`، `code` یا `term`. برای واحدهای چندخطیِ خاص می‌توان `unit_id` مشترک داد. بدون فرادادهٔ نوع، عنوان Markdown، فهرست و فرمول‌های کاملِ `$...$`/`\(...\)` نیز شناسایی می‌شوند.

تابع `translate_prepared(lines, request, ...)` یک callback به نام `request` می‌گیرد؛ ورودی callback یک prompt JSON با `items`، واژه‌نامه و در حالت سند زمینهٔ قبلی است و خروجی آن باید آرایهٔ JSON `[{"id":1,"text":"..."}]` باشد. حباب‌های هر صفحه یک درخواست دارند. در سند `batch_size` قابل تنظیم است، فقط پاراگراف بزرگ‌تر از حد و فقط در مرز جمله تقسیم می‌شود؛ جملهٔ تنهای بزرگ‌تر از حد از وسط شکسته نمی‌شود. `glossary` در هر درخواست می‌رود، ترجمهٔ واحدهای `kind="term"` بعد از دسته به آن اضافه می‌شود و برای یادگیری منابع دیگر نیز callback اختیاری `learn_terms` موجود است. فرمول و کد ارسال نمی‌شوند و عیناً برمی‌گردند. ناهماهنگی تعداد/ترتیب/id فقط یک بار با همان prompt retry می‌شود و پاسخ ناسازگار دوم خطا می‌دهد.

ثابت‌های `DEFAULT_MODE`، `VERTICAL_GAP_THRESHOLD` و `BATCH_SIZE_CHARS` در ابتدای `text_preparation.py` قابل تنظیم‌اند.

## مدل‌ها و حریم خصوصی

- OCR روی همین کامپیوتر انجام می‌شود. در حالت عادی، اجرای OCR حق دانلود مدل ندارد.
- PP-OCRv6 Small در بستهٔ آزمایش‌شدهٔ RapidOCR 3.10.0 همراه مدل‌های لازم است و روی CPU آزمایش شده است.
- PP-OCRv5 و EasyOCR فقط از دکمهٔ «آماده‌سازی / دانلود مدل» یا نصب آگاهانهٔ بستهٔ مربوط آماده می‌شوند. این دکمه در صورت نبودن بسته، آن را با Python خود برنامه نصب می‌کند و فقط زبان انتخاب‌شده را آماده می‌کند. برای PP-OCRv5 مدل‌ها در پوشهٔ دادهٔ برنامه نگهداری می‌شوند.
- Tesseract با خروجی TSV و مختصات خط پشتیبانی می‌شود. در صورت نصب نبودن برنامهٔ اجرایی آن در ویندوز (یا لینوکس دارای مدیر بسته)، با زدن دکمهٔ «آماده‌سازی / دانلود خودکار» موتور اجرایی رسمی به‌صورت بی‌صدا در پوشهٔ دادهٔ برنامه نصب می‌شود و فایل زبان انتخاب‌شده نیز از `tessdata_fast` رسمی دریافت می‌گردد. پس از آن اجرای OCR به اینترنت نیاز ندارد.
- در پنجرهٔ مدل‌ها، همهٔ ۹ مدل پیشرفته (`PaddleOCR-VL-1.6`، `Surya`، `MinerU2.5-Pro`، `GOT-OCR 2.0`، `GLM-OCR`، `dots.ocr`، `DeepSeek-OCR-2`، `olmOCR` و `HunyuanOCR`) نیز به‌همراه چهار موتور سبک کمیک با یک کلیک در محیط‌های مجازی ایزوله (`models/envs/<engine>`) نصب و دانلود می‌شوند و خروجی آن‌ها به کادرهای قابل‌ویرایش کمیک تبدیل می‌گردد. پیش از دانلود مدل‌های سنگین نیازمند کارت گرافیک NVIDIA یا فضای دیسک بالا، سیستم به‌طور خودکار بررسی می‌شود و در صورت نبود کارت گرافیک یا حافظهٔ کافی هشدار فارسی نمایش داده می‌شود. همچنین انتشار نسخهٔ جدید برای مدل‌های نصب‌شده بررسی شده و با دکمهٔ «به‌روزرسانی به نسخهٔ جدید» با یک کلیک قابل ارتقاست.
- دقت روی صفحات واقعی کمیک برای همهٔ زبان‌ها هنوز اندازه‌گیری نشده است؛ دکمهٔ آزمایش برای مقایسهٔ واقعی روی تصویر خودتان است.
- ترجمهٔ رایگان و AI آنلاین به اینترنت نیاز دارند و تصویر را ارسال نمی‌کنند؛ AI علاوه بر OCR، دستور، اسکیل و خلاصهٔ داستان را نیز ارسال می‌کند. برای AI محلی می‌توانید نشانی یک سرویس محلی سازگار با OpenAI وارد کنید.
- کلیدهای API فقط در فایل تنظیمات محلی برنامه ذخیره می‌شوند و در پاسخ‌های API یا رابط نمایش داده نمی‌شوند. در سیستم‌عامل‌های پشتیبان، مجوز فایل روی `0600` تنظیم می‌شود. مدل و نام دلخواه ردیف‌ها قابل نمایش‌اند، اما پاسخ عمومی فقط `hasApiKey` را دارد.

### اگر هنگام نصب Torch خطای WinError 32 دیدید

این خطا یعنی ویندوز اجازهٔ دسترسی به فایل موقت wheel را نداد، چون فرایند دیگری آن را نگه داشته است؛ معمولاً نصب هم‌زمان، یک Python/pip باز یا بررسی آنتی‌ویروس است و به معنی خرابی مدل نیست. برنامه حالا نصب بسته‌هایش را یکی‌یکی انجام می‌دهد، اما برای نصب دستی:

1. پنجرهٔ برنامه، PowerShellها و نصب‌کننده‌های Python/pip دیگر را ببندید و یک بار ویندوز را Restart کنید.
2. اگر پوشهٔ `pip-unpack-...` در `%TEMP%` باقی مانده بود، فقط بعد از بستن نصب‌کننده‌ها آن را حذف کنید.
3. همان محیط `.venv` را دوباره با **یک** فرمان نصب اجرا کنید؛ دکمهٔ آماده‌سازی را پشت‌سرهم نزنید.
4. اگر ادامه داشت، فایل را در آنتی‌ویروس بررسی کنید و برای نصب از محیط تازه با Python 3.11 یا 3.12 استفاده کنید. فایل را فقط از منابع رسمی دریافت کنید.

## محل داده‌ها

به‌صورت پیش‌فرض پروژه‌ها و مدل‌های دانلودشده در `~/.comic-ocr-studio/` هستند، نه در پوشهٔ افزونه. برای تغییر محل:

```bash
COMIC_STUDIO_DATA=/path/to/data .venv/bin/python run.py
```

## آزمایش‌ها

```bash
.venv/bin/pip install -e '.[ocr,dev]'
.venv/bin/pytest
# آزمایش عمدی مدل واقعی، بدون دانلود خودکار:
COMIC_STUDIO_REAL_OCR=1 .venv/bin/pytest -m real_ocr
# آزمون مستقل منطق گروه‌ها و بررسی نحوی رابط:
node tests/groups.test.js
node tests/typeset_overlay.test.js
node tests/app_ui.test.js
node --check comic_studio/static/app.js
```

از ریشهٔ مخزن نیز `npm test` تست‌های افزونهٔ 2.58 را بدون تغییر در کد آن اجرا می‌کند. برای آزمون واقعی مسیر ترجمه/ویرایش تا پیش‌نمایش و دانلود در Chromium:

```bash
npm install
npm run test:studio-browser
```

این آزمون روی Linux با Node.js 22.17 یا جدیدتر اجرا می‌شود؛ یک سرور و پروژهٔ موقت جدا می‌سازد، با کنترل‌های واقعی صفحه کار می‌کند و پیکسل‌های ZIP/PDF و متن TXT دانلودشده را بررسی می‌کند؛ پروژه‌های کاربر تغییر نمی‌کنند. برای اتصال AI نیز یک سرویس محلی ساختگی OpenAI-compatible راه می‌افتد و مسیر واقعی «کلیک تست → FastAPI → خواندن مدل» بدون تماس خارجی یا مصرف سهمیه آزمایش می‌شود. پاسخ مترجم در آزمون کنترل‌شده است، اما canvas، آپلود رندر و دانلود مرورگر واقعی‌اند.

## امنیت و دسترسی شبکه

حالت عادی فقط روی `127.0.0.1` اجرا می‌شود و نیازی به رمز ندارد. بدون تنظیم رمز، برنامه درخواست کلاینت‌های غیر-loopback و نام میزبان غیرمحلی را رد می‌کند؛ بازکردن پورت با `--host 0.0.0.0` به‌تنهایی دسترسی شبکه نمی‌دهد. درخواست‌های مرورگر از مبدأ دیگر نیز برای عملیات تغییر داده رد می‌شوند. این کنترل‌ها امنیت کامل را در برابر برنامه‌های دیگر روی همان رایانه یا پیکربندی نادرست پروکسی تضمین نمی‌کنند.

اگر عمداً دسترسی شبکه یا hostname پروکسی نیاز دارید، یک رمز تصادفی و طولانی حداقل ۲۰ نویسه در متغیر محیطی `COMIC_STUDIO_ACCESS_PASSWORD` تنظیم کنید. سپس **تمام** درخواست‌ها، از جمله localhost و فایل‌های رابط، احراز هویت HTTP Basic می‌خواهند: نام کاربری `comic` و رمز همان متغیر است. رمز کوتاه باعث خطای ۵۰۳ می‌شود و در پاسخ درج نمی‌شود. سرور خودِ برنامه TLS ندارد: HTTP Basic روی HTTP ساده رمز را آشکار می‌کند؛ فقط از HTTPS در پروکسی معتبر یا VPN مورد اعتماد استفاده کنید، از گذرواژهٔ قوی و فایروال استفاده کنید و برنامه را مستقیماً در اینترنت عمومی قرار ندهید. پروکسی باید `Host` و scheme صحیح را منتقل و headerهای ارسالی کلاینت را پاک‌سازی کند؛ در پروکسی loopback حتماً رمز برنامه یا احراز هویت مستقل پروکسی فعال باشد. برای پیش‌نمایش HTTPS پشت پروکسی نیز باید همین رمز تنظیم شود.

مثال PowerShell، بعد از نصب و از داخل پوشهٔ `python_app`، برای نشست فعلی (رمز را برای ورود یادداشت و پس از پایان نشست حذف کنید):

```powershell
$env:COMIC_STUDIO_ACCESS_PASSWORD = .\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"
Write-Host $env:COMIC_STUDIO_ACCESS_PASSWORD
.\.venv\Scripts\python.exe run.py --host 0.0.0.0 --port 8765
# پس از پایان کار: Remove-Item Env:COMIC_STUDIO_ACCESS_PASSWORD
```

کلیدهای API همچنان رمزگذاری‌شده نیستند و در `~/.comic-ocr-studio/ai-settings.json` یا مسیر `COMIC_STUDIO_DATA` ذخیره می‌شوند. فایل موقت و فایل نهایی در POSIX از ابتدا با مجوز `0600` ساخته می‌شوند؛ روی Windows این مقدار جایگزین تنظیم ACL ویندوز نیست و باید پوشهٔ حساب کاربری محافظت شود. در POSIX برنامه تلاش می‌کند مجوز فایل تنظیمات موجود و فایل موقت قدیمی آن را نیز محدود کند؛ فایل موقت قدیمی حذف نمی‌شود و در صورت خطای مجوز ممکن است نیاز به اصلاح دستی باشد. بک‌آپ فایل تنظیمات و کلیدهای ذخیره‌شدهٔ API را شامل نمی‌شود، اما خود OCR، ترجمه و پیش‌نویس می‌توانند اطلاعات محرمانه داشته باشند.

## اجرای API بدون رابط پیش‌فرض

برنامه با FastAPI ساخته شده است؛ رابط اصلی همان فایل‌های محلی `comic_studio/static/` است و تمام درخواست‌های مرورگر نسبی هستند. برای اجرای مستقیم سرور:

```bash
.venv/bin/uvicorn comic_studio.main:app --host 127.0.0.1 --port 8765
```
