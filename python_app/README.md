# Comic OCR Studio 3.34

برنامهٔ مستقل Python برای کار روی خروجی افزونه: **PDF یا تصویر ورودی → OCR → ترجمه/AI → ویرایش → PDF، ZIP تصویر یا TXT**.

این برنامه به افزونه وصل نمی‌شود و هیچ تصویری از وب‌سایت جمع‌آوری نمی‌کند. افزونه فقط جمع‌آورندهٔ تصاویر سایت باقی می‌ماند.

## نصب برنامه از شاخهٔ GitHub

برای نصب **خود برنامه** از شاخهٔ `arena/343b59d6-comicccc`، در ویندوز این کارها را انجام دهید:

1. Python 3.11 یا جدیدتر و Git را نصب کنید. در نصب Python گزینهٔ **Add Python to PATH** را فعال کنید.
2. PowerShell را در پوشه‌ای که می‌خواهید برنامه در آن باشد باز کنید و اجرا کنید:

```powershell
git clone --branch arena/343b59d6-comicccc --single-branch https://github.com/sargoliwork101-ui/COMICCCC.git
cd COMICCCC\python_app
.\start_windows.bat
```

اگر Git ندارید، صفحهٔ [همین شاخه](https://github.com/sargoliwork101-ui/COMICCCC/tree/arena/343b59d6-comicccc) را باز کنید، از **Code → Download ZIP** فایل را بگیرید، آن را Extract کنید و سپس داخل پوشهٔ `python_app` فایل `start_windows.bat` را اجرا کنید. لازم نیست مخزن‌های مدل‌های دیگر را برای نصب برنامه دانلود کنید.

لینک‌های روی کارت‌های «اجرای جداگانه» مربوط به پروژه‌های خارجی هستند. آن‌ها داخل Comic OCR Studio نصب یا اجرا نمی‌شوند؛ اگر خواستید جداگانه از آن‌ها استفاده کنید، باید دستورهای **README همان مخزن رسمی** را در یک محیط جدا دنبال کنید. خروجی آن‌ها هم فعلاً به کادرهای قابل ویرایش این برنامه تبدیل نمی‌شود.

## اجرا

### ویندوز — ساده‌ترین روش

فایل **`start_windows.bat`** را در همین پوشه دابل‌کلیک کنید. در اجرای اول، فایل Python 3.11 یا جدیدتر را پیدا می‌کند، محیط جداگانهٔ `.venv` می‌سازد، همهٔ وابستگی‌های لازم را نصب می‌کند و سپس برنامه را باز می‌کند. در اجراهای بعدی، نصب تکرار نمی‌شود و برنامه مستقیم باز می‌شود. اجرای اول به اینترنت برای دریافت بسته‌ها نیاز دارد.

اگر Python در PATH نباشد، فایل مسیر استاندارد Python 3.13 را هم بررسی می‌کند. در صورت نمایش خطای نصب، متن خطا را در همان پنجره بخوانید؛ پنجره به‌صورت خودکار بسته نمی‌شود.

#### نصب OCR با دسترسی مدیر در ویندوز

برای استفادهٔ عادی به Administrator نیاز نیست. اگر هنگام نصب بستهٔ OCR خطای **Access is denied / WinError 5** گرفتید، برنامه را ببندید و فایل **`start_windows_admin.bat`** را در همین پوشه اجرا کنید. ویندوز یک پیام UAC نشان می‌دهد؛ بعد از تأیید شما، همان launcher و برنامه با دسترسی مدیر باز می‌شوند و نصب OCR از پنجرهٔ «مدل‌های OCR و آزمایش» نیز همین دسترسی را دارد. اگر برنامه قبلاً با دسترسی مدیر باز باشد، درخواست دوباره نمایش داده نمی‌شود.

این launcher به‌تنهایی مدل اختیاری دانلود نمی‌کند؛ آماده‌سازی و دانلود هر مدل همچنان فقط با کلیک شما انجام می‌شود. دسترسی مدیر برای خطای قطع اینترنت یا قفل‌شدن فایل توسط برنامهٔ دیگر راه‌حل نیست؛ در آن حالت متن خطای همان نصب را دنبال کنید.

### اجرای دستی

به Python 3.11 یا جدیدتر نیاز است. در همین پوشه:

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[ocr]'
.venv/bin/python run.py
```

در ویندوز، به‌جای `.venv/bin/...` از `.venv\\Scripts\\...` استفاده کنید. نشانی پیش‌فرض `http://127.0.0.1:8765` است. فقط در نخستین اجرای تعاملی، برنامه به **انگلیسی** می‌پرسد کدام مرورگر (پیش‌فرض، Edge، Chrome یا Firefox) و کدام حالت بازشدن (زبانه در مرورگر باز یا پنجرهٔ جدید) را می‌خواهید. انتخاب در `browser-preferences.json` داخل پوشهٔ دادهٔ برنامه ذخیره می‌شود و اجراهای بعدی بدون سؤال از آن استفاده می‌کنند. برای تغییر انتخاب دائمی، این فایل را حذف کنید تا سؤال دوباره ظاهر شود؛ گزینه‌های دستی `--browser` و `--window` نیز برای همان اجرا اولویت دارند. اگر مرورگر انتخاب‌شده نصب نباشد، برنامه بی‌صدا به Edge برنمی‌گردد.

برای اجرای بدون سؤال می‌توانید انتخاب را از قبل بدهید:

```bash
.venv/bin/python run.py --browser firefox --window new
.venv/bin/python run.py --browser chrome --window existing
```

«همان مرورگرِ باز» یعنی درخواست زبانهٔ جدید به نمونهٔ در حال اجرای مرورگر؛ برنامه محتوای زبانه‌های فعلی شما را تغییر نمی‌دهد. در اجرای غیرتعاملی و بدون این گزینه‌ها، رفتار پیش‌فرض سیستم استفاده می‌شود.

اگر نمی‌خواهید مرورگر خودکار باز شود:

```bash
.venv/bin/python run.py --no-browser
```

اجرای بدون بستهٔ OCR هم ممکن است، اما برای استفاده از PP-OCR باید extra به نام `ocr` نصب شود. OpenCV headless جزو وابستگی‌های پایه است تا پیش‌پردازش‌های اختیاری OCR برای موتورهای دیگر نیز کار کنند؛ این بسته به‌تنهایی مدل OCR دانلود نمی‌کند. نصب بسته‌ها و آماده‌سازی مدل‌ها باید با انتخاب شما انجام شود. در ویندوز، راه‌انداز پس از به‌روزرسانی نسخه وابستگی‌ها را دوباره بررسی و نصب می‌کند.

## امکانات

- ورود چند فایل تصویری یا PDF؛ صفحات PDF به تصویرهای قابل ویرایش تبدیل می‌شوند.
- پروژه‌های ذخیره‌شونده روی کامپیوتر، انتخاب همه/هیچ/معکوس و انتخاب محدوده با Shift، ترتیب دستی و کشیدن کارت‌ها، کپی و حذف؛ حذف پروژه نیز از منوی پروژه ممکن است.
- مدیریت کامل گروه‌ها: ساخت و ادغام، شماره و رنگ، کادر دور اعضا، انتخاب گروه، ویرایش عضوها، لغو گروه، جابه‌جایی گروه به‌صورت یک بلوک و مرتب‌سازی داخل گروه. رهاکردن روی وسط کارت گروه می‌سازد، رهاکردن نزدیک لبه جابه‌جا می‌کند و رهاکردن عضو در فضای خالی او را از گروه خارج می‌کند.
- رابط تیره/روشن با چیدمان، کارت‌ها و نوار خروجی مشابه افزونه؛ نام و تنظیمات پروژه خودکار ذخیره می‌شوند.
- پیش‌نمایش صفحهٔ اصلی هنگام بازکردن پروژه و بعد از ترجمه/ویرایش از آخرین متن ساخته می‌شود؛ یک رندر قدیمی‌تر نمی‌تواند نسخهٔ تازه را جایگزین کند.
- بعد از ساخت PDF، ZIP یا TXT، پیوند «دانلود» در بخش وضعیت باقی می‌ماند؛ اگر دانلود خودکار مرورگر انجام نشد، همان فایل با این پیوند قابل دریافت است.
- OCR محلی با PP-OCRv6 Small؛ PP-OCRv5 Multilingual و EasyOCR به‌عنوان گزینهٔ جداگانه.
- اگر OCR اصلی خالی، خیلی کوتاه یا کم‌اطمینان باشد، یک تلاش اختیاری با بزرگ‌نمایی ۳×، جداسازی پیکسل‌های بسیار روشن و معکوس‌کردن رنگ انجام می‌شود؛ نتیجه فقط وقتی بهتر است جایگزین می‌شود.
- مسیر اختیاری «پیش‌پردازش حباب» نیز فقط بعد از ضعیف‌بودن OCR اصلی اجرا می‌شود: کانتور تیره با `MORPH_CLOSE 25×25` و حداقل مساحت 8000، mask با erode به اندازهٔ 15، میانه و یکدستی پس‌زمینه 55٪ در بازهٔ ±20، استخراج جوهر با ضریب 0.45، بزرگ‌نمایی ۳× و حاشیهٔ سفید 30 پیکسل. نواحی با میانگین confidence کلمات زیر 60 حذف می‌شوند، حباب‌ها از بالا به پایین خوانده می‌شوند و برای Tesseract از `--psm 6` استفاده می‌شود. بهترین نتیجه در میان OCR اصلی و fallbackها انتخاب می‌شود؛ همهٔ آستانه‌ها در ابتدای `ocr.py` قابل تنظیم‌اند.
- پس از OCR، گزینهٔ پیش‌فرض «ادغام خودکار خط‌های نزدیک در یک کادر حباب» خط‌های نزدیک با هم‌پوشانی افقی را به یک متن و کادر تبدیل می‌کند؛ مثلاً `WHY ARE YOU` و `RUNNING AROUND` به `WHY ARE YOU RUNNING AROUND` تبدیل می‌شوند. تشخیص تنها بر اساس موقعیت است و همیشه مرز واقعی حباب را نمی‌فهمد؛ می‌توان گزینه را خاموش کرد. در ویرایشگر با Ctrl/⌘ و کلیک چند کادر را انتخاب کنید و «ادغام متن‌ها» را بزنید، یا یک کادر ادغام‌شده را انتخاب و «جداکردن خط‌ها» را بزنید. خط‌ها و مختصات اصلی ذخیره می‌شوند. برای جلوگیری از ازدست‌رفتن ترجمه و ویرایش، ادغام دستی فقط پیش از ترجمه و جداسازی پیش از ترجمه و تغییر متن ادغام‌شده مجاز است. پروژه‌های قبلی تا اجرای دوبارهٔ OCR یا ادغام دستی خودبه‌خود تغییر نمی‌کنند.
- آزمایش موتور روی نخستین تصویر انتخاب‌شده بدون تغییر دادن پروژه.
- کلیک روی تصویر یا کارت و یک کلیک روی کادر تیک، انتخاب را تغییر می‌دهد؛ حتی بعد از ذخیرهٔ خودکار نیازی به دو کلیک نیست. دکمهٔ چشم فقط پیش‌نمایش را باز می‌کند و تصویرهای انتخاب‌نشده کمی خاکستری و کم‌نور می‌شوند تا وضعیتشان روشن باشد.
- کارت‌های مدل زیر هم نمایش داده می‌شوند؛ Escape پنجرهٔ باز را می‌بندد و سربرگ پنجره‌ها هنگام اسکرول در دسترس می‌ماند.
- بخش «گزارش زندهٔ کارها» مراحل ورود فایل، نصب/دانلود مدل، OCR، ترجمه و خروجی را همان لحظه نشان می‌دهد. بعد از OCR، متن واقعی خوانده‌شدهٔ هر تصویر نیز خط‌به‌خط در گزارش می‌آید؛ پیام موفق با علامت سبز و متن خوانا نمایش داده می‌شود.
- در اجرای معمولی با `run.py` یا راه‌انداز ویندوز، بستن آخرین زبانهٔ برنامه پس از مهلت کوتاه سرور Python را خاموش می‌کند. heartbeat جلوی خاموش‌شدن هنگام refresh یا بازبودن زبانهٔ دیگر را می‌گیرد.
- پیش از هر ترجمه در رابط، پنجره‌ای متن کامل و دقیق همهٔ درخواست‌ها را به ترتیب ارسال نشان می‌دهد و تا کلیک «تأیید و ارسال برای ترجمه» هیچ متنی به مترجم نمی‌رود. این پیش‌نمایش برای دکمهٔ اصلی و «ترجمهٔ دوباره»ٔ هر کادر مشترک است؛ مقصد، مدل، نشانی AI و دستور سیستم نیز دیده می‌شوند. سرویس رایگان Google Translate و fallback احتمالی MyMemory را جدا معرفی می‌کند. تغییر متن/پروژه یا مدل و نشانی AI امضای پیش‌نمایش را باطل می‌کند و پیش‌نمایش تازه لازم است.
- در سرویس رایگان، متن OCR کادرها با خط جدید معمولی و بدون جداکنندهٔ ویژه ترکیب می‌شود. اگر متن جمعی حداکثر ۵۰۰ نویسه باشد، یک query جمعی فرستاده می‌شود؛ برای چند کادر پاسخ باید تعداد خطوط و جای خط‌های خالی متن مبدأ را حفظ کند تا به هر کادر تعداد خط‌های خودش برگردد. پاسخ ناسازگار ذخیره نمی‌شود. یک کادر منفرد به تقسیم نیاز ندارد و ترجمهٔ چندخطی آن نیز پذیرفته می‌شود. برای متن جمعی بلندتر از ۵۰۰ نویسه، کادرها جدا و queryهای طولانی در مرز جمله تا حد ممکن تقسیم می‌شوند.
- اتصال AI از **Google Gemini، OpenAI، OpenRouter و AvalAI** پشتیبانی می‌کند. متن کادرها با خط جدید و context مشترک در یک درخواست می‌رود؛ برای چند کادر، تعداد خط‌ها و جای خط‌های خالی قبل از پذیرش هر کلید بررسی می‌شود و در صورت پاسخ ناسازگار کلید بعدی همان سرویس امتحان می‌شود. هر سرویس تنظیمات و کلیدهای جداگانهٔ خود را دارد. خروجی نامعتبر ذخیره نمی‌شود و فقط متن OCR ارسال می‌شود، نه تصویر.
- شمارش خطوط نمی‌تواند جابه‌جایی معنایی خط‌ها توسط مترجم را تشخیص دهد؛ پس از ترجمه، ترتیب و محتوای کادرها را بازبینی کنید. اگر پروژه هنگام OCR، ترجمه یا ورود فایل در جای دیگری تغییر کند، نتیجه برای جلوگیری از بازنویسی ذخیره نمی‌شود و باید دوباره تلاش کنید.
- بعد از OCR متن اصلی و بعد از ترجمه، متن ترجمه روی تصویر قرار می‌گیرد. انتخابگرهای «متن روی تصویر» سه حالت «ترجمه»، «متن اصلی OCR» و «بدون متن» دارند و پیش‌نمایش را بلافاصله بازسازی می‌کنند. «بدون متن» تصویر اصلی را برای پیش‌نمایش و PDF/ZIP برمی‌گرداند، اما OCR و ترجمهٔ ذخیره‌شده پاک نمی‌شوند؛ پروژه‌های قبلی به‌صورت پیش‌فرض در حالت ترجمه می‌مانند.
- ویرایش متن OCR و ترجمه روی خود تصویر یا در کارت متن، قالب‌بندی غنی، فهرست، خط‌خورده، واگرد/ازنو، راست‌به‌چپ/چپ‌به‌راست و تراز راست، وسط، چپ و **جاستیفای**. در جاستیفای، خط‌هایی که خودکار شکسته‌اند از دو طرف تراز می‌شوند؛ خط آخر و خطِ پیش از شکست دستی کشیده نمی‌شوند. نشانگر فهرست نیز در تصویر رندر می‌شود.
- با کلیک روی متن یا کادر خالی تصویر، ویرایشگر شناور کنار همان کادر باز می‌شود. هر Enter خط/پاراگراف مستقلی می‌سازد؛ نشانگر را روی خط بگذارید و از ابزار «خط انتخاب‌شده» برای تراز، جهت، اندازه و رنگ مستقل آن استفاده کنید. خطی که فقط به‌علت عرض کادر خودکار شکسته می‌شود، همچنان بخشی از همان پاراگراف است. تنظیمات مستقل در پیش‌نمایش، ذخیره و خروجی تصویر/PDF حفظ می‌شوند؛ اندازه فقط بر تصویر اثر دارد، نه اندازهٔ نوشتهٔ کادر ویرایش.
- تغییر متن و تنظیمات ابتدا در پیش‌نویس می‌مانند؛ «ثبت و نمایش» نتیجه را در همان تصویر به‌روزرسانی می‌کند و با لغو می‌توان تغییرها را کنار گذاشت. اگر فضا بالای کادر کافی نباشد، پنجره داخل بخش قابل‌دید تصویر قرار می‌گیرد. کارت کناری و ابزارهای گروهی همچنان در دسترس‌اند. این ویرایشگر از الگوی [بلوک پاراگراف وردپرس](https://wordpress.org/documentation/article/paragraph-block/) الهام گرفته و خود ویرایشگر وردپرس یا تمام امکانات آن نیست.
- اندازه و رنگ قلم هر کادر به تصویر و خروجی مربوط‌اند، نه اندازهٔ خواندن متن در ویرایشگر؛ کنترل‌های کم/زیاد و بازگشت به اندازه یا رنگ خودکار نیز وجود دارند. اندازهٔ دستی بزرگ ممکن است از ارتفاع کادر بیشتر و در لبهٔ آن بریده شود؛ در این صورت کادر را بزرگ‌تر یا اندازه را کمتر کنید.
- متن زیر لایهٔ ویرایش با همان `Typeset.render` خروجی و به‌ترتیب «همهٔ پاک‌سازی‌ها، همهٔ پس‌زمینه‌ها، سپس همهٔ متن‌ها» ساخته می‌شود؛ بنابراین هم‌پوشانی واقعی هنگام تایپ/کشیدن دیده می‌شود و پس‌زمینهٔ کادر بعدی متن قبلی را نمی‌پوشاند.
- زبان نمایش هر متن مستقل است: با دکمهٔ فا/EN روی کادر یا انتخابگر «نمایش همین متن» در کارتش می‌توان فقط همان متن را «فارسی / ترجمه» یا «انگلیسی / OCR» کرد. انتخاب‌ها ذخیره می‌شوند و در پیش‌نمایش و PDF/ZIP می‌توان بعضی کادرها فارسی و بعضی انگلیسی باشند. انتخاب کلی، پیش‌فرض متن‌های بدون انتخاب جداگانه است و «بدون متن» همچنان همه را پنهان می‌کند.
- نمایش/عدم‌نمایش هر خط مستقل از خطوط دیگر است: دکمهٔ 👁 روی همان کادر آن را پنهان می‌کند و تیک «نمایش متن … روی تصویر» در کارت همان خط، آن را پنهان یا دوباره نمایان می‌کند. این انتخاب در پیش‌نمایش و PDF/ZIP حفظ می‌شود و متن OCR یا ترجمهٔ خط پنهان حذف نمی‌شود.
- جابه‌جایی و تغییر اندازهٔ کادر ترجمه با هشت دستگیره، برش تصویر با هشت دستگیره و نسبت‌های ثابت، پیش‌نمایش برش‌خورده و کپی تصویر.
- انتخاب چند متن با Ctrl/⌘ + کلیک یا «انتخاب همه»؛ **اولین کادر انتخاب‌شده مرجع است** و دکمهٔ «هم‌اندازه با اولی» عرض و ارتفاع همهٔ کادرهای دیگر را، حتی با بیش از دو انتخاب، از آن کپی می‌کند. کادر مرجع در این عمل ثابت می‌ماند، مرکز هر هدف تا جای ممکن حفظ و کادر داخل مرز تصویر نگه داشته می‌شود. تراز گروهی چپ، وسط افقی، راست، بالا، وسط عمودی و پایین و جابه‌جایی گروهی با ⠿ نیز موجود است؛ مختصات ناحیهٔ پاک‌سازی OCR تغییر نمی‌کند و نتیجه به پیش‌نمایش و PDF/ZIP می‌رسد.
- خروجی PDF معمولی، قاب‌های هم‌اندازه، دو تصویر در صفحه و حالت seamless؛ اعضای هر گروه با حفظ نسبت ابعاد و یکسان‌سازی عرض، به‌صورت عمودی به یک صفحه تبدیل می‌شوند و در حالت دو-تصویر، گروه از هم نمی‌شکند. خروجی ZIP با فرمت اصلی/PNG/JPEG و خروجی متنی با تورفتگی نیز موجود است.

### تنظیم و تست اتصال هوش مصنوعی

1. از «پروژه و تنظیمات ← ترجمهٔ رایگان / AI» سرویس را انتخاب کنید. نام مدل باید دقیقاً همان شناسهٔ موجود در همان سرویس باشد؛ برنامه مدل دیگری را جایگزین آن نمی‌کند.
2. برای هر کلید یک نام دلخواه و خود کلید را وارد کنید. با «افزودن API» می‌توانید کلیدهای بیشتری برای همان سرویس بسازید و با × ردیف اضافی را حذف کنید.
3. «تست» همان ردیف ابتدا تنظیمات را ذخیره می‌کند و سپس فقط مشخصات/فهرست مدل را می‌خواند. در این تست متن کمیک یا درخواست تولید ترجمه ارسال نمی‌شود؛ موفقیت یعنی کلید معتبر است و مدل انتخاب‌شده در فهرست پاسخ وجود دارد.
4. «ذخیره» را بزنید و ترجمه را اجرا کنید. اگر کلیدی خطای دسترسی، سهمیه، شبکه یا پاسخ غیرقابل‌استفاده بدهد، کلید بعدی همان سرویس فقط یک بار امتحان می‌شود. خطا با نام ردیف و بدون نمایش secret گزارش می‌شود؛ برنامه به‌جای آن به سرویس دیگر یا ترجمهٔ رایگان سؤال‌نشده نمی‌رود.

کلید ذخیره‌شده به مرورگر برگردانده نمی‌شود؛ فیلد خالی بعد از ذخیره یعنی همان کلید قبلی حفظ شده است. تنظیمات قدیمی تک‌کلیدی AvalAI/OpenAI هنگام خواندن به فضای سرویس متناسب منتقل می‌شوند. برای OpenAI و سرویس محلی سازگار می‌توانید «نشانی پایهٔ API» را تغییر دهید؛ برای Gemini، OpenRouter و AvalAI نیز نشانی پیش‌فرض رسمی همان سرویس استفاده می‌شود.

### مسیر اختیاری آماده‌سازی متن برای ترجمه

ماژول `comic_studio.text_preparation` یک مسیر **جدید و opt-in** برای ساخت واحدهای ترجمه است؛ مسیر فعال فعلی برنامه، امضای `TranslationService.translate()`، ساختار OCR و API پروژه را تغییر نمی‌دهد. تابع `prepare_translation_units(lines, mode=...)` با `bubble` خطوط هر ناحیه را از بالا به پایین به حباب‌های جدا تبدیل می‌کند و با `document` پاراگراف‌ها و واحدهای خاص را جدا نگه می‌دارد. نوع واحد سند با `kind` روی خط مشخص می‌شود: `heading`، `list_item`، `table_cell`، `formula`، `code` یا `term`. برای واحدهای چندخطیِ خاص می‌توان `unit_id` مشترک داد. بدون فرادادهٔ نوع، عنوان Markdown، فهرست و فرمول‌های کاملِ `$...$`/`\(...\)` نیز شناسایی می‌شوند.

تابع `translate_prepared(lines, request, ...)` یک callback به نام `request` می‌گیرد؛ ورودی callback یک prompt JSON با `items`، واژه‌نامه و در حالت سند زمینهٔ قبلی است و خروجی آن باید آرایهٔ JSON `[{"id":1,"text":"..."}]` باشد. حباب‌های هر صفحه یک درخواست دارند. در سند `batch_size` قابل تنظیم است، فقط پاراگراف بزرگ‌تر از حد و فقط در مرز جمله تقسیم می‌شود؛ جملهٔ تنهای بزرگ‌تر از حد از وسط شکسته نمی‌شود. `glossary` در هر درخواست می‌رود، ترجمهٔ واحدهای `kind="term"` بعد از دسته به آن اضافه می‌شود و برای یادگیری منابع دیگر نیز callback اختیاری `learn_terms` موجود است. فرمول و کد ارسال نمی‌شوند و عیناً برمی‌گردند. ناهماهنگی تعداد/ترتیب/id فقط یک بار با همان prompt retry می‌شود و پاسخ ناسازگار دوم خطا می‌دهد.

ثابت‌های `DEFAULT_MODE`، `VERTICAL_GAP_THRESHOLD` و `BATCH_SIZE_CHARS` در ابتدای `text_preparation.py` قابل تنظیم‌اند.

## مدل‌ها و حریم خصوصی

- OCR روی همین کامپیوتر انجام می‌شود. در حالت عادی، اجرای OCR حق دانلود مدل ندارد.
- PP-OCRv6 Small در بستهٔ آزمایش‌شدهٔ RapidOCR 3.10.0 همراه مدل‌های لازم است و روی CPU آزمایش شده است.
- PP-OCRv5 و EasyOCR فقط از دکمهٔ «آماده‌سازی / دانلود مدل» یا نصب آگاهانهٔ بستهٔ مربوط آماده می‌شوند. این دکمه در صورت نبودن بسته، آن را با Python خود برنامه نصب می‌کند و فقط زبان انتخاب‌شده را آماده می‌کند. برای PP-OCRv5 مدل‌ها در پوشهٔ دادهٔ برنامه نگهداری می‌شوند.
- Tesseract نیز با خروجی TSV و مختصات خط اضافه شده است. فایل اجرایی آن باید جداگانه از پروژهٔ رسمی نصب شود؛ فایل زبان انتخاب‌شده فقط با کلیک کاربر از `tessdata_fast` رسمی دانلود و در پوشهٔ دادهٔ برنامه نگهداری می‌شود. پس از آن اجرای OCR به اینترنت نیاز ندارد.
- در پنجرهٔ مدل‌ها، PaddleOCR-VL-1.6، MinerU2.5-Pro، GLM-OCR، DeepSeek-OCR-2، GOT-OCR 2.0، dots.ocr، olmOCR، HunyuanOCR و Surya نیز با لینک رسمی دانلود/راه‌اندازی فهرست شده‌اند. این‌ها فعلاً در بخش «اجرای جداگانه» هستند و در فهرست OCR داخلی انتخاب نمی‌شوند: بیشتر آن‌ها VLM یا پایپ‌لاین تحلیل سندند، به حافظه/Backend جدا نیاز دارند و خروجی مستقیم آن‌ها کادرهای خط‌به‌خط لازم برای ویرایش کمیک نیست. برنامه برای این موارد وزن چندگیگابایتی دانلود نمی‌کند و وضعیت آمادهٔ ساختگی نمایش نمی‌دهد.
- دقت روی صفحات واقعی کمیک برای همهٔ زبان‌ها هنوز اندازه‌گیری نشده است؛ دکمهٔ آزمایش برای مقایسهٔ واقعی روی تصویر خودتان است.
- ترجمهٔ رایگان و AI آنلاین به اینترنت نیاز دارند و فقط متن OCR را ارسال می‌کنند، نه تصویر را. برای AI محلی می‌توانید نشانی یک سرویس محلی سازگار با OpenAI وارد کنید.
- کلیدهای API فقط در فایل تنظیمات محلی برنامه ذخیره می‌شوند و در پاسخ‌های API یا رابط نمایش داده نمی‌شوند. در سیستم‌عامل‌های پشتیبان، مجوز فایل روی `0600` تنظیم می‌شود. مدل و نام دلخواه ردیف‌ها قابل نمایش‌اند، اما پاسخ عمومی فقط `hasApiKey` را دارد.

### اگر هنگام نصب Torch خطای WinError 32 دیدید

این خطا یعنی ویندوز اجازهٔ دسترسی به فایل موقت wheel را نداد، چون فرایند دیگری آن را نگه داشته است؛ معمولاً نصب هم‌زمان، یک Python/pip باز یا بررسی آنتی‌ویروس است و به معنی خرابی مدل نیست. برنامه حالا نصب بسته‌هایش را یکی‌یکی انجام می‌دهد، اما برای نصب دستی:

1. پنجرهٔ برنامه، PowerShellها و نصب‌کننده‌های Python/pip دیگر را ببندید و یک بار ویندوز را Restart کنید.
2. اگر پوشهٔ `pip-unpack-...` در `%TEMP%` باقی مانده بود، فقط بعد از بستن نصب‌کننده‌ها آن را حذف کنید.
3. همان محیط `.venv` را دوباره با **یک** فرمان نصب اجرا کنید؛ دکمهٔ آماده‌سازی را پشت‌سرهم نزنید.
4. اگر ادامه داشت، فایل را در آنتی‌ویروس بررسی کنید و برای نصب از محیط تازه با Python 3.11 یا 3.12 استفاده کنید. فایل را فقط از منابع رسمی دریافت کنید.

## محل داده‌ها

به‌صورت پیش‌فرض پروژه‌ها و مدل‌های دانلودشده در `~/.comic-ocr-studio/` هستند، نه در پوشهٔ افزونه. برای تغییر محل:

```bash
COMIC_STUDIO_DATA=/path/to/data .venv/bin/python run.py
```

## آزمایش‌ها

```bash
.venv/bin/pip install -e '.[ocr,dev]'
.venv/bin/pytest
# آزمایش عمدی مدل واقعی، بدون دانلود خودکار:
COMIC_STUDIO_REAL_OCR=1 .venv/bin/pytest -m real_ocr
# آزمون مستقل منطق گروه‌ها و بررسی نحوی رابط:
node tests/groups.test.js
node tests/typeset_overlay.test.js
node tests/app_ui.test.js
node --check comic_studio/static/app.js
```

از ریشهٔ مخزن نیز `npm test` تست‌های افزونهٔ 2.55 را بدون تغییر در کد آن اجرا می‌کند. برای آزمون واقعی مسیر ترجمه/ویرایش تا پیش‌نمایش و دانلود در Chromium:

```bash
npm install
npm run test:studio-browser
```

این آزمون روی Linux با Node.js 22.17 یا جدیدتر اجرا می‌شود؛ یک سرور و پروژهٔ موقت جدا می‌سازد، با کنترل‌های واقعی صفحه کار می‌کند و پیکسل‌های ZIP/PDF و متن TXT دانلودشده را بررسی می‌کند؛ پروژه‌های کاربر تغییر نمی‌کنند. برای اتصال AI نیز یک سرویس محلی ساختگی OpenAI-compatible راه می‌افتد و مسیر واقعی «کلیک تست → FastAPI → خواندن مدل» بدون تماس خارجی یا مصرف سهمیه آزمایش می‌شود. پاسخ مترجم در آزمون کنترل‌شده است، اما canvas، آپلود رندر و دانلود مرورگر واقعی‌اند.

## اجرای API بدون رابط پیش‌فرض

برنامه با FastAPI ساخته شده است؛ رابط اصلی همان فایل‌های محلی `comic_studio/static/` است و تمام درخواست‌های مرورگر نسبی هستند. برای اجرای مستقیم سرور:

```bash
.venv/bin/uvicorn comic_studio.main:app --host 127.0.0.1 --port 8765
```
